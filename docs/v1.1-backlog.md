- **现象**：侧栏按作用域分组后，「搜索」归入文档级分组，但实现仍是**全工作区**检索——在当前文档里找个词，先把整个工作区每帧扫一遍，结果按文件分组铺开，与旁边只看活动文档的大纲 / 检查形成语义断层。
- **修复**（纯展示层重组 + 一层范围过滤，领域与应用服务零改动）：
  - 状态层 `SearchScope { CurrentDocument, Workspace }`（默认当前文档、会话内有效不落偏好）+ `SEARCH_SCOPES`；输入框占位提示随范围变化。
  - `SearchQuery.only_document: Option<DocumentId>`；服务在候选收集后、读盘前 retain——「当前文档」范围下逐个读全工作区文件是最贵路径，必须在此砍掉。用 ID 而非路径：未落盘草稿同样有 ID，且天然复用「草稿优先于磁盘内容」规则。
  - `search_workspace()`：当前文档 + 无活动文档 → 返回空结果（**不**退化成全工作区，否则界面声明的范围与实际搜索对象矛盾）；空状态文案由视图负责。
  - 视图：输入框下新增范围切换行（`selectable_label` 两段式，形态与顶部标签栏 / 大纲层级条一致；「搜谁」先于「怎么搜」故紧贴输入框）。
- **取舍**：默认「当前文档」而非沿用旧的跨文件默认——分组后文档级是主路径；跨文件作为可切换形态保留（真实高频能力），不做成下拉（两个选项 + 需常瞥见当前范围，一次点击到位）。
- **回归**：`search_can_be_limited_to_one_document`（应用层）、`search_scope_current_document_only_searches_the_open_file` 与 `clicking_the_scope_switcher_changes_the_search_scope`（表现层，点击落点取字形中心不写死坐标）、状态层单测；两处守卫均做过「改坏必失败」的有效性验证。
- **后续**：布局重构其余部分（活动栏分组、面板折叠、窄屏浮层等）见设计方案，按用户确认的顺序开工。

### V11-30 · 用户反馈三项修复（保存全部 / 标签条 / 快捷键重置入口，2026-10-15）｜P1

- **现象**（用户一条消息提 3 项，截图 ×1）：① 应用级菜单「文件 → 保存全部」点击后无任何反应；② 标签条需要「打开文档数量限制（设置页可调）+ 合适位置『全部关闭』按钮 + 标签多时单行横向滚动」（截图实证当前为竖向逐行堆叠）；③ 设置页「恢复默认快捷键」埋在快捷键列表滚动区最底部，60 个条目要滑很久才能看到。
- **修复**（纯展示层 + 一个偏好字段 + 一处动作接线）：
  - **保存全部**：根因是 `EditorApp::execute` 的 `_ => {}` 兜底吞掉了 `UiAction::SaveAll`——动作表、菜单（`MenuGroup::APP_LEVEL`）、快捷键（`Ctrl+Alt+S`）、命令面板四个入口都有，唯独汇聚点没接线（与 `Ctrl+S`/`Ctrl+N` 同根因）。新增 `save_all_documents()`：收集脏文档 → 逐个 `SaveCommand{save_as:false}` + `clear_draft` → 无路径者单独计数（未命名，提示「需先另存为」）→ 失败收集不中断 → 汇总提示。
  - **打开数量限制**：`EditorSettings` 新增 `max_open_documents`（默认 12，范围 1..=30）。**serde 入口把 0 收敛为 1**——`TomlPreferencesRepository::load()` 对校验失败的处理是「备份 + 整体回退默认」，为单字段 0 丢掉用户全部配置不可接受；`is_valid` 保留 0 非法判定作不变量。限额检查在**去重之后**：已打开文档走「切换」不占新名额，否则会挡住「切回已打开文档」这个最常见操作。`open_workspace_file` 与 `new_document` 两处覆盖。
  - **「全部关闭」按钮**：常驻标签条右端（量宽 + 固定矩形 + 1px 分隔线 + 手绘 hover），关最后一个标签与按钮同险同防；有脏文档走原生确认框（复用 V11-06 的 `pending_*` + `DialogRunner` 后台确认模式，新增 `pending_close_all`，Confirm 出口按「哪个 pending 有值」分流）。
  - **标签条竖向**：`ScrollArea` 内层 Ui **继承父级 `top_down` 布局**，`allocate_exact_size` 纵向推进光标导致逐行堆叠——横向是**内层 Ui 的属性**（`ui.horizontal_top`）而非滚动区属性；滚动条可见时在视口**内部占位**（`inner_size = outer_size − bar_use`）会吃掉 24pt 行高一截并附带引出无用的竖向条，故用 `AlwaysHidden`（只隐藏绘制，滚轮/拖拽仍可滚）。
  - **快捷键重置入口**：从快捷键列表滚动区移入设置对话框页脚（与「恢复本组默认」互斥显示），页脚锚点用「取消」而非「保存」（列表里也有「保存」动作名）。
- **回归**：新增 `save_all_test`（5 例，含失败不中断与未命名计数）、`open_limit_test`（5 例，含「上限时仍可切回已打开文档」这个最易写坏处）、`close_all_confirm_test`（7 例）、`tab_strip_test`（4 例，含「全部关闭」在溢出时仍可见与单行锚定）、`restore_default_shortcuts_button_lives_in_the_footer`（滚到底后按钮 y 不变）；仓储层补「手改 0 收敛为 1 且无备份」与「缺字段按 12 读出」。
- **详细取证与逐步记录**：问题记录 038。
