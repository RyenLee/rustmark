### V11-04 · PDF 导出开放决策与实现｜P1

- **任务内容**：基础设施 `SystemPdfExporter` 已就绪（三平台探测有单测），但产物须经系统打印对话框中转（用户拿不到直接落盘的 `.pdf`，`bytes` 恒为 0）。需**先定 UX**：
  - 方案 A：独立「打印导出」入口（语义诚实：调起系统打印对话框）；
  - 方案 B：直接开放 PDF 格式并明确提示「经系统对话框保存」。
- **预期目标**：选定方案并实现；同步更新 README 功能表（去掉 ⛔）、`export_view.rs` 文案、相关测试。
- **验收依据**：PDF 导出端到端可用（或在方案 A 下入口可用）；文档与代码一致。
- **注意**：ADR-004 明确「不内嵌 PDF 引擎」，两条方案都不违背体积预算。
- **完成记录（2026-10-09）**：采用**方案 B**——直接开放 PDF 格式，但明确提示「经由系统打印对话框产出，请在对话框中选择『另存为 PDF』」。关键改动：`ExportAppService::create_job` 不再以硬编码拒绝 PDF；`SystemPdfExporter` 把打印副作用抽为可注入的 `PrintDispatcher` 端口（测试用 `FakeDispatcher` 验证「写入 HTML → 派发打印 → 报告 0 字节」，以及派发失败干净报错），从而 CI 不必真弹打印框。旧「PDF 未实现」单测改写为「PDF 被诚实提供并给出系统打印提示」；`export_ui_state` 的 PDF 占位文案改为实际可用的说明。
- **修订记录（2026-10-10，ADR-004 修订）**：上线后用户报告 Windows 导出直接报错（`Start-Process : Cannot validate argument on parameter 'FilePath'. The argument is null or empty.`）。根因两处叠加：① `powershell -Command <字符串> <参数…>` 的尾随参数**不进 `$args`**（且被当作脚本正文另起语句执行），故 `-FilePath $args[0]` 恒为 `null`；② `printto` 动词指向**已废弃**的 MSHTML 打印引擎且必须经打印对话框。**决策调整为 Windows 优先无头 Chromium（Edge → Chrome）的 `--print-to-pdf`**（Edge 随 Windows 10/11 预装，零新增 crate，不违背「不内嵌引擎」立场），`printto` 降为兜底；调用路径改走**环境变量**而非命令行参数。顺带修复「纸张选项从未注入 `@page`」（现按 `ExportOptions::page_size` 注入 `@page{size:A4|letter;margin:18mm}`）与「大小恒报 0」（能落盘时回报真实字节数，`PdfBackend::writes_pdf` 把「是否真落盘」暴露给界面）。本机实测产物为真 PDF（`%PDF-` 头）、静默无窗口。**遗留**：该链路对应的真实用例 `real_export_writes_a_real_pdf_to_the_chosen_path` 在本会话环境不通过（无头浏览器不可用，见 V11-15）。

### V11-12 · 规范 15 机械门禁（生产代码禁用 `unwrap` / `expect` / `panic!`）｜P1

- **背景**：`.agent/conventions.md` §四-15 与 `CONTRIBUTING.md` §4 都规定「生产代码禁用 `unwrap()` / `expect()` / `panic!`」，但**没有机械检查**——`clippy` 默认不开 `unwrap_used` / `expect_used`，`check-arch` 只管分层。规范靠人工 review 执行，容易被遗忘。
- **现状（2026-10-09 审计）**：`src/` 下共 61 处 `unwrap()` / `expect()`，其中 **14 处不在 `#[cfg(test)]` 上下文**：
  - `src/app/frame.rs:1925` —— 前方有 `let Some(_id) = self.active_doc else { return; }` 守卫，不可达；
  - `src/application/markdown/service.rs` 6 处 —— 均为 `Mutex::lock().expect("…锁已损坏")`；`panic = "abort"` 下 panic 不展开，Mutex 不会被 poison，实际不可达；
  - `src/application/workspace/service.rs:359`、`src/infrastructure/persistence/encoding.rs:144`、`src/presentation/views/editor_ops.rs` 2 处、`src/presentation/views/sidebar_view.rs:314` —— 各有局部不变式保障，但缺机械证明。

- **现象与根因**：预览报「当前版本未内置 TLS」。S5-11 为体积拒绝一切 HTTP 客户端 crate，手写 `TcpStream` + 裸 HTTP/1.0，https 被**硬编码拒绝**——历史前提（图片多为 http）已不成立（CSDN / GitHub / 对象存储图床几乎全是 https）。
- **修复**：引入 `ureq 3.4.2`（`default-features=false` + `["rustls"]`，纯 Rust TLS、三平台一致、无系统依赖）；`load_remote` 保留三条边界：全局超时（5s）、边读边判体积硬上限、MIME 白名单（响应头优先、缺失按重定向后最终 URL 扩展名推断）；非成功状态码显式报 `DownloadFailed`；`split_http_body` 随 TcpStream 方案退役。
- **回归**：`https_connect_failure_returns_download_error_not_panic`（保留端口必须降级，panic=abort 下坏图引用不得终止进程）；`real_https_download`（`#[ignore]` 需外网）——用户报障的原始 CSDN 地址实测下载成功（image/gif, 2056 bytes）。
- **体积代价**：登记于 `docs/dependencies.md` §1 与 `docs/metrics.md` §2.4；详细记录：问题记录 026。
