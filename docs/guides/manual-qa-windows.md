## 0. 适用范围

## 1. 环境准备

1. 用 `cargo build --release` 产物（或安装包）在**干净** Windows 机器上测试，不要用 debug 构建估性能。
2. 准备一个含中文与空格的目录：`C:\Users\<你>\文档\Markdown 笔记\你好世界\`。
3. 准备 1MB+ 的 `.md` 样本（可由 `tests/common/golden_fixture.rs` 生成）放到上述目录。
4. 准备一台默认打印机（或确认无打印机时 PDF 导出给出 HTML 回退提示）。
5. 缩放档位：100% / 125% / 150% / 200% 各测一轮（Windows 显示设置 → 缩放与布局）。
6. 准备一个 **GBK 编码**的中文 `.md`（记事本「另存为 → 编码 → GB2312」即可）。这是验证 §2.10 的必需样本，Windows 上历史中文文档多为 GBK。
7. 确认中文字体存在：`dir %WINDIR%\Fonts\msyh.ttc`（微软雅黑）。**Windows 缺失此项时中文将显示为方框**，见 §2.4。

- **MQ-W-02** 125%：整体等比放大，无半像素缝隙；状态栏与工具栏不溢出。

- **MQ-W-04** 200%（高分屏）：长时间滚动后字号仍稳定，不出现「放大后又缩小」抖动。
- **MQ-W-05** 在应用运行中切换系统缩放：应用应跟随（eframe 的 `ctx.pixels_per_point()` 在 `theme/mapper.rs` 读取），不出现黑边或重叠。

### 2.2 中文路径 / 非 ASCII 文件名（P0，需截图）

- **MQ-W-09** 文件名含中文 + 英文混合（`Hello世界.md`）：最近文件列表、标签页标题显示正常。
- **MQ-W-10** 保存到**尚未存在**的子目录（另存为到新文件夹）：`atomic_write` 会 `create_dir_all`，不报错。

### 2.4 字体 / CJK 渲染（P0，需截图）

> **实测结论（务必按此判断，勿凭直觉）**：egui 0.33 内置字体族**不含任何 CJK 字形**，
> 所以「Windows 的 `system-ui` 会自动回退到微软雅黑」这一旧假设**不成立**——
> 不加载系统中文字体时，界面中文**必然**是占位方框（`□`）。
> 现已由 `infrastructure/fonts.rs` 在首帧前把 `%WINDIR%\Fonts` 下的
> `msyh.ttc → Deng.ttf → simhei.ttf → simsun.ttc` 依次探测并**追加到字体族末尾**。
> 。

- **MQ-W-16** 界面所有中文（菜单、工具栏、侧栏、状态栏、弹窗）显示清晰，无豆腐块（`□`）、无问号、无空白。**逐屏翻一遍，不要只看编辑区**——缺字形在编辑区最显眼，容易掩盖其他位置的同类问题。
- **MQ-W-16b** 状态栏、标签页标题、导出面板等**次要位置**的中文同样正常。这两处字体族不同（比例族 / 等宽族），只验一处可能漏掉「等宽族漏挂 CJK」这类半边故障。
- **MQ-W-16c** 代码块内的中文注释：等宽对齐不被破坏。若代码块缩进出现错位，说明 CJK 字体被插到了族**开头**（会接管西文字形并破坏等宽），而非追加到末尾——这是必须能一眼看出的回归。
- **MQ-W-16d** 工具栏图标（`√` 勾、`×` 叉）与符号面板全部条目**有字形**、不成方框。历史问题码位 `✓(U+2713)`、`✕(U+2715)`、`✗(U+2717)` 在 egui 默认字体下无字形，已替换为 `√(U+221A)` / `×(U+00D7)`；符号面板另有 `▤→≡`、`▦→▣`、`ⓘ→ℹ`、`⏎→↩`、`⇒→↔`、`❝→"`、`🤔→💭`。
- **MQ-W-16e** emoji（📄 ✅ ❌ ⭐ 💡）正常显示。这批由**随包分发的** NotoEmoji / emoji-icon-font 覆盖（`fonts/` 目录，REL-03 起不再内嵌进 exe；缺失时该目录代号位回落系统字体），与 CJK 字体是两套链路，需分别确认。
- **MQ-W-17** 在设置里把字号调到 20px：编辑器与预览区同步放大，行高倍数（`line_height`，默认 1.6）保持。
- **MQ-W-18** 输入中文（用系统 IME 输入法，如微软拼音）：候选框不遮挡编辑区，输入进文档后光标位置正确（IME 属 S7-01 转交项，必须真机验）。

> **注**：加载的是常规**轮廓**字体，候选清单刻意不含 `seguiemj.ttf` / `NotoColorEmoji.ttf`
> 等彩色 emoji 字体——egui 底层 `ab_glyph` 只吃 glyf/CFF 轮廓，且本项目 `panic = "abort"`，
> 解析 panic 会直接终止进程。

### 2.5 文件编码（GBK / BOM）（P0，需截图）

> **背景**：本项目**读取**支持 UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM、GBK/CP936；
> **保存统一写 UTF-8**。判定乱码时先分清两类：
> `□`/`?` 是**缺字形**（看 §2.4），`锟斤拷`/`æ–‡ç«`/`�`(U+FFFD) 是**解码错**。

- **MQ-W-28** 打开 §1.6 准备的 GBK 文件：中文**完全正确**，无 `�`、无 `锟斤拷`、无方块。这是本节最重要的一条。
- **MQ-W-28b** GBK 文件中的中英混排段落（ASCII 区间与 UTF-8 兼容）不粘连、不丢字符：GBK 尾部若跟ASCII 字母，被吞掉即为回归（曾出现的真实缺陷：非法首字节导致后继字符丢失）。
- **MQ-W-28c** 对该 GBK 文件执行保存 → 重开：内容一致，但**文件已是 UTF-8**（这是当前已知限制，不是缺陷，见 §4）。状态栏编码项显示 `UTF-8` 且**不可点击**——本应用不提供编码切换开关。
- **MQ-W-28d** 打开 UTF-8（含/不含 BOM）与 UTF-16 LE/BE 文件：均正常；UTF-16 文件首行**不应**出现 `�`（U+FFFD）。
- **MQ-W-28e** 打开一个**真正损坏**的文件（用二进制编辑器写入非法字节序列，如 `[0x61,0xFF,0x62]`）：应保留可读字符 `ab`、非法处降级为 `�`，**不得整篇变乱码、不得崩溃**。
- **MQ-W-28f** 导出 HTML：用浏览器打开，`<meta charset="utf-8">` 位于 `<head>` 首部（charset 须在前 1024 字节内才生效，当前满足），中文正常。导出 CSS 的正文字体族已加入微软雅黑 / 苹方 / Noto CJK 回退。

### 2.6 视口截图导出（P1，需截图）

> 能力边界：PNG 走 egui 官方回路（`ViewportCommand::Screenshot` → GPU 回读 → `crop`），
> 因此**截的是预览区在窗口中的可见部分**，不是整篇长图。UI 上已明示该范围。

- **MQ-W-29** 导出面板选 PNG：得到文件可在系统看图工具正常打开，非空白、非全黑。
- **MQ-W-29b** PNG 内容与**当前预览区所见一致**（含中文、代码块高亮、表格线）；滚动后再截一次，画面随滚动位置变化。
- **MQ-W-29c** 在 150% / 200% 缩放下截图：分辨率随DPI 放大，文字**不锯齿糊化**、不错位（官方回路保留抗锯齿，这是自研光栅化做不到的）。
- **MQ-W-29d** 预览区被窗口边缘裁切时截图：画面与所见一致，**不崩溃、不产生半张图**；越界请求应报错而非静默夹紧。
- **MQ-W-29e** 导出面板中「范围＝预览区在窗口中的可见部分」的说明文字存在且准确（避免用户误以为能导出整篇长图）。

### 2.7 打印 / PDF 导出（P1，需截图）

- **MQ-W-19** 导出 PDF：后端探测 `powershell`（`Start-Process -Verb PrintTo`）。有默认打印机时弹出系统打印对话框；**无打印机**时返回可读性错误并建议「先导出 HTML 再打印」（`system_pdf_exporter.rs` 的 `IoUnavailable` 文案）。
- **MQ-W-20** 导出 HTML：文件含 `<meta charset="utf-8">` 与内联 `<style>`（自动化已验 `exported_html_keeps_charset_and_style`）。用浏览器打开中文不乱码。

### 2.8 文件对话框（原生，rfd）（P1，需截图）

- **MQ-W-21** 打开 / 另存为弹出**系统原生**对话框（非自制），过滤器只列 `.md` 相关。

### 2.9 大文件降级观感（FPS）（P1，需截图）

- **MQ-W-23** 打开 1MB 文件：预览区进入降级路径（`truncated=true`，不渲染全文），滚动流畅，编辑区不卡顿（自动化已验降级触发，但**帧率**只能真机看）。
- **MQ-W-24** 大文件下输入即触发全文查找：默认大小写不敏感时**可能卡顿**，记录主观延迟；修复后重测。

## 3. 平台差异处置表

| 维度 | Windows | 与 macOS 差异 | 与 Linux 差异 | 处置 |
|---|---|---|---|---|
| 主修饰键 | `Ctrl` | macOS 为 `⌘`（模型内 `ctrl` 字段映射 Cmd） | `Ctrl` | 键位字符串统一写 `Ctrl+…`，分发层按平台映射 |
| 路径分隔 | 内部归一为 `/`（rfd 返回 `\` 时替换） | 原生即 `/` | 原生即 `/` | 跨平台一致，Windows 需重点验 `\→/` |
| 打印后端 | `powershell` `PrintTo` | `lp`（CUPS） | `lp` / `lpstat` | 探测函数各平台不同文案，UI 给对应提示 |
| 中文字体来源 | `%WINDIR%\Fonts`：`msyh.ttc → Deng.ttf → simhei.ttf → simsun.ttc` | `/System/Library/Fonts/PingFang.ttc` 等 | `/usr/share/fonts/…` Noto CJK / 文泉驿 / 文泉驿微米黑 | **egui 内置字体无 CJK，三平台均须显式加载并追加到族末尾**；缺字体不阻塞启动，仅打印明确警告 |
| 文件编码 | 读取 UTF-8/BOM/GBK，保存 UTF-8 | 同 | 同 | 编码探测与解码是平台无关的纯逻辑，三平台共用同一实现与同一组测试 |
| 文件对话框 | rfd 原生（Win32） | rfd 原生（Cocoa） | rfd 原生（GTK） | 行为一致，均验取消语义 |

## 4. 已知风险 / 遗留

- **DEF-01**（大小写不敏感查找 O(N×M)）：大文件下编辑区查找卡顿，待 S6-08 修复。
- **DEF-02**（自动保存 / 草稿恢复运行时未接线）。
- **DEF-03**（编码转换只做单向读）：读取支持 GBK，但**保存一律写 UTF-8**。打开 GBK 后另存为不会写回 GBK——需要保留原编码的用户目前做不到。
- **DEF-04**（GB18030 / Big5 / Shift_JIS 未支持）：遇到这些编码的文件会按 GBK 规则解码，可能出现替换字符。四个平台同此限制。
- **DEF-05**（PNG 仅覆盖可见视口）：整篇长图导出尚未实现，需离屏重建布局，见 §2.6。
- 字体探测只收录**常规轮廓字体**，刻意不含彩色 emoji 字体（`ab_glyph` 不支持 COLR/CBDT，而 `panic = "abort"` 下解析失败即终止进程）。
- macOS / Linux 的字体候选路径**未在本机验证**，需真机确认（MQ-M-14 / MQ-L-14）。
- 截图保真度与混合 DPI 场景仍需真机验证（自动化只能验裁剪、尺寸上限、PNG 落盘往返）。
- IME、像素级观感、滚动 FPS 无法自动化，是手工回归的核心价值。
