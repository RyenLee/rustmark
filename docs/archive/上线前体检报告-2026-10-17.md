## 二、发现（按严重级）

### CRITICAL-1（已修复）：cargo-deny licenses 红 —— egui 0.37 升级遗留
egui 0.37 引入的两个新 crate 许可证未入 `deny.toml` allowlist，**CI 的 deny 门禁会红**：
- `epaint_default_fonts 0.37`：`(MIT OR Apache-2.0) AND OFL-1.1 AND Ubuntu-font-1.0`
- `webpki-roots 1.0.9`（ureq 链）：`CDLA-Permissive-2.0`

**已代改** `deny.toml`：allow 列表补 `OFL-1.1`、`Ubuntu-font-1.0`、`CDLA-Permissive-2.0`
（三者均为字体/根证书数据类许可，允许随二进制嵌入分发；如对许可政策有异议请回滚该改动另行评估）。
复验：`cargo deny check licenses` → **licenses ok**。`bans` / `sources` 本来就绿。
遗留小噪声：`MIT-0`、`Unicode-DFS-2016` 两条失效 allow 产生 warning（依赖已移除，可择机清理）。

### CRITICAL-2（待决策）：体积红线恶化 —— 10.93 → 13.46 MiB
- 实测：`target/x86_64-pc-windows-msvc/release/rustmark.exe` = **14,116,352 bytes = 13.46 MiB**
  （口径与 metrics.md §2.5 相同：release profile opt-level=z + LTO + strip=true 的文件总大小）。
- 对比 2026-10-14 基线 **10.93 MiB**：**+2.53 MiB（+23%）**，时间上对应 egui 0.33→0.37 /
  wgpu 27→30 升级批次，疑为主要增量来源（未归因）。
- 影响：`NFR-PERF-01`（≤10 MB）越线从 0.93 扩大到 **3.46 MiB**；打包脚本内 ≤10MB 门禁必然红。
- 处置建议：`cargo bloat --release --bin rustmark --crates 25` 复测归因，确认增量是否来自
  wgpu 30 / egui 0.37 / 图片解码链，再决定是否触发 metrics.md §2.4 的缓解方案。
