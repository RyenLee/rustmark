## 1. 阶段目标

把「功能完整」打磨成「指标达标」。本项目的差异化定位就是**体积 ≤ 10 MB、冷启动 ≤ 2s、空闲内存按平台可达**（§1.2，内存阈值经 ADR-006 修订为「按平台各自阈值」，Windows ≤ 150 MB / Private Working Set），这三项未达标则产品定位不成立，因此本阶段不可压缩。

所有优化必须以**阶段 01 定义的测量口径**产出数字，禁止凭感觉判断。

## 3. 任务清单

### S8-01 体积基线与预算表落地

- **描述**：用 `cargo bloat --release --crates 20` 与平台打包工具实测各组件体积贡献，产出实际预算表（对照 §8.1 的预估：egui+eframe 3–4 MB、pulldown 0.44 MB、syntect 0.8–1.5 MB、ropey 0.15 MB、rfd+serde 0.5 MB、应用代码 0.5–1 MB）。找出超出预估的组件并定位其传递依赖（`cargo tree -i <crate>`）。
- **前置依赖**：S5-03、S7-05
- **涉及文件**：`docs/metrics.md`、`docs/optimization-log.md`
- **验收标准**：预算表含「预估 / 实测 / 偏差 / 处置」四列；偏差 > 30% 的组件有明确说明；总预算分配写入 `docs/`，后续新增依赖需引用该表。

### S8-02 syntect 语言集裁剪与 dump 优化

- **描述**：若实测 syntect > 1.5 MB，按 ADR-002 的分级预案裁剪（20 → 10 → 5 种语言）；同步验证 dump 加载耗时（目标 ≤ 30ms，§8.2 预期 23ms）；确认 dump 文件是否计入安装包体积（若计入则评估压缩或按需下载）。
- **前置依赖**：S8-01、S5-03
- **涉及文件**：`src/infrastructure/highlighting/syntect_highlighter.rs`、`build.rs`
- **验收标准**：syntect 贡献 ≤ 1.5 MB；裁剪后 20 种目标语言中保留的语言有完整 golden 用例，被裁语言回退到纯文本不高亮且有提示；若触发 fallback（自研 regex 高亮），补 ADR-002 修订版并说明覆盖的 token 集。

### S8-03 启动优化（目标 300–500ms）

- **描述**：落实 §8.2 三项：① 语法集/主题集二进制 dump；② 非关键路径（文件对话框、图片加载器、最近文件读盘）异步初始化；③ 窗口骨架先显示、UI 内容延迟填充（首帧只画工具栏与空编辑区，解析与高亮在首帧后提交）。
- **前置依赖**：S6-01、S8-02
- **涉及文件**：`src/app/frame.rs`、`src/app/bootstrap.rs`
- **验收标准**：三平台冷启动 ≤ 2s 且记录 p50（目标 300–500ms）；启动耗时分解表（进程启动 / 语法集加载 / 首帧 / 内容就绪）写入 `docs/metrics.md`；异步初始化失败不阻塞主窗口。

### S8-04 内存优化（阈值经 ADR-006 修订：Windows ≤ 150 MB / Private Working Set）

- **描述**：落实 §8.3：① `Rope` 作为唯一文本缓冲（确认无全文 `String` 副本常驻）；② `LayoutJob` LRU 上限 64；③ 预览 `Galley` 缓存（仅版本变化时重建）；④ 图片 `TextureHandle` 缓存 + 解码后降采样；⑤ 撤销栈快照上限（每文档保留条数上限，避免长会话无界增长）。
- **前置依赖**：S5-01、S6-04、S6-05、S5-11
- **涉及文件**：`src/presentation/**`、`src/infrastructure/persistence/asset_loader.rs`
- **验收标准**：空白文档空闲内存按平台阈值达标（**ADR-006**：Windows 判定口径改为 **Private Working Set**，阈值 ≤ 150 MB；WorkingSet64 / macOS footprint / Linux VmRSS 三口径仍各记录一次，静置 10s 后取值）；打开 1MB 文档后内存曲线有上限（不随编辑时长无界增长）；撤销栈上限生效（断言条数）。

### S8-05 增量高亮与可视区降级（FR-03 / FR-06）

- **描述**：确认 S6-04 的增量高亮在真实交互下只重建变更行；> 500KB 文档仅高亮可视区；超长单行（如 10 万字符无换行）有行级保护（截断高亮而非整行渲染）。
- **前置依赖**：S6-04、S7-04
- **涉及文件**：`src/presentation/views/editor_view.rs`
- **验收标准**：单行编辑时重建行数 == 1（调试计数器断言）；10KB 文档全文高亮 ≤ 10ms；1MB 文档滚动不掉帧（记录帧时间 p95 ≤ 16ms）；超长单行不卡死。

### S8-06 预览防抖与解析性能（FR-01 / NFR-PERF-06）

- **描述**：确认 150ms 防抖在连续输入下只触发一次重解析；10KB 文档解析 ≤ 5ms；解析在首帧后异步提交，不阻塞输入。用阶段 07 的真实输入节奏校准撤销合并窗口（初值 400ms）与防抖间隔。
- **前置依赖**：S4-06、S6-05、S7-01
- **涉及文件**：`src/application/markdown/service.rs`、`docs/metrics.md`
- **验收标准**：连续输入 20 字符期间重解析次数 ≤ 2（调试计数）；10KB 解析耗时 ≤ 5ms（记录 p50/p95）；合并窗口与防抖间隔的实测校准结论写入文档（若调整需说明理由）。

### S8-07 CI 体积与性能门禁

- **描述**：在阶段 02 的 CI 上增加：① 体积门禁（三平台产物字节数超阈值即 fail，阈值 10 MB，预警线 8 MB）；② 性能冒烟 job（跑解析/高亮/编辑响应三个微基准，超阈值 fail）；③ `cargo bloat` 结果作为构建摘要输出。
- **前置依赖**：S8-01、S8-05、S8-06
- **涉及文件**：`.github/workflows/ci.yml`、`benches/**`（可选 `criterion`，注意体积与编译时间成本）
- **验收标准**：人为把阈值调低可验证门禁确实 fail；每次 PR 摘要可见三平台产物体积；基准 job 在三平台稳定（波动范围内），不稳定则标记为「仅 Linux 必过」。

### S8-08 优化决策记录

- **描述**：把本阶段每次优化的手段、前后数字、副作用写进 `docs/optimization-log.md`；对「做了但无效」与「有效但有代价」的两类决策同样记录，避免后续重复尝试。
- **前置依赖**：S8-01 ~ S8-07
- **涉及文件**：`docs/optimization-log.md`
- **验收标准**：≥ 8 条记录，每条含「手段 / 前值 / 后值 / 代价 / 结论」；明确列出放弃的优化项及原因。

## 4. 技术方案要点

- **先测量后优化**：所有优化项必须有前后对比数字；`docs/metrics.md` 是唯一数字来源，禁止在代码注释里散落性能结论。
- **`panic = "abort"` + `opt-level = "z"` + `lto = true`** 已在前置阶段设定（§8.1），本阶段验证其实际收益与编译时间代价，若编译时间不可接受可评估 `opt-level = "s"` 的折中（需记录体积变化）。
- **降级策略是功能不是缺陷**：> 500KB 仅高亮可视区是需求明确要求（FR-06），需在 UI 上有可感知但不打扰的提示（如状态栏标记），避免用户误判为 bug。
- **内存与体积的权衡**：缓存（LRU 64、Galley、纹理）用内存换响应时间；上限值必须可配置，以便低配设备上调小。

## 5. 风险与注意事项

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| **体积超标** | 高 | 三平台任一 > 10 MB | M1 起 CI 监控（已在 S2-08）；syntect 分级裁剪（S8-02）；最终 fallback 自研 regex 高亮；必要时砍 P1/P2 特性（数学公式/Mermaid/自定义主题）换体积 |
| 启动优化收益不及预期 | 中 | 冷启动 > 1s | 拆分测量定位瓶颈（语法集 vs 字体加载 vs 首帧渲染）；考虑字体子集化或延迟加载 |
| 内存测量口径争议 | 中 | 三平台数字不可比 | S8-04 三口径各记一次并在文档中注明不可直接横向比较；门禁以「各平台各自阈值」为准 |
| 优化引入回归 | 中 | 增量高亮结果与全量不一致 | S5-03 已有一致性用例（增量 vs 全量）；S8-05 后重跑该用例 |
| 基准不稳定导致 CI 抖动 | 中 | 性能门禁随机红 | 基准 job 标记为非阻塞或仅 Linux 必过；阈值留 30% 余量 |
| 编译时间过长影响迭代 | 低 | release 构建 5–10 分钟 | 日常开发用 dev profile；release 只在 CI 与发布时构建 |
