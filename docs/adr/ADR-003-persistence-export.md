# ADR-003 · 持久化、文件对话框与导出

- **状态**：已接受（2026-10-06）
- **关联需求**：§4.3、§5.1、§3.2（`FR-04`、`FUNC-P0-11/12`、`FUNC-P1-04`、`NFR-REL-02/03`）
- **关联任务**：S1-04、S3-11、S4-04、S5-04、S5-05、S5-06、S5-09、S5-11

## 背景

ADR-001 否决了 Tauri 与 SQLite，因此 v1.0 的持久化必须回到「本地文件 + 配置文件」。需要固化三件事：文档保存的原子性（`FR-04`）、配置持久化格式与迁移、图片资源策略（原型在此处踩过两个坑）。

## 决策

### 1. 文档保存：原子写

落盘步骤固定为：

1. 在**目标文件同一目录**写入临时文件 `<name>.rustmark-tmp-<pid>`；
2. 写入完成后 `flush` + `fsync`；
3. `rename` 覆盖目标文件（同分区 rename 为原子操作）；
4. 失败时删除临时文件，**保留原文件不动**，返回 `Err`。

附加规则：

- 编码：读取时识别 UTF-8 BOM 与 CRLF，内部统一 LF；写回时还原原始 BOM/换行风格（`DocumentMeta` 记录 `line_ending`）；
- **保存失败不得清除脏标记**（防止用户误以为已保存）；
- 草稿：自动保存写独立草稿文件，启动检测到草稿时提示「发现未保存草稿，是否恢复」，恢复或丢弃后清理草稿文件（`NFR-REL-03`）。

### 2. 配置持久化：`serde` + `toml`

- 文件：`settings.toml`（路径遵循各平台配置目录规范）；
- **schema 版本字段 `version: u32` 必填**；版本不匹配或文件损坏时：备份原文件为 `settings.toml.bak` → 回退默认值 → 提示用户；
- 未知字段忽略（向前兼容），缺失字段用默认值填充；
- 写入同样采用原子写。

### 3. 文件对话框：`rfd 0.17.2`

- 原生对话框，扩展名过滤 `.md` / `.markdown` / `.txt`；
- 用户取消返回 `Err(Cancelled)`，**不返回空路径**（避免调用方误判）；
- 按 §8.2 要求异步初始化（首次调用前的预热放在启动后的空闲帧）。

### 4. 图片资源策略

原型在此处有两个已实测的缺陷，本决策直接继承其正面结论：

| 原型缺陷 | 本决策 |
|---|---|
| `safeUrl` 未放行 `data:image/*` → 粘贴的图在预览/导出/打印全不可见 | 精确白名单 `data:image/(png\|jpeg\|jpg\|gif\|webp\|bmp);base64,` 放行 |
| `data:` 整体放行会导致 `data:text/html;base64,` XSS | **只放行上述 image 子集**，`data:text/html` 继续拒绝 |
| 图片内联导致文档膨胀、localStorage 静默写满 | 体积上限改为**硬约束**：超限返回明确 `Err` 并提示导出/改用相对路径，不做「仅 warn 不阻断」 |

- 三种来源均支持：本地相对路径（相对文档/工作区解析）、远程 URL（带超时）、`data:image`；
- 解码后按显示宽度降采样；纹理缓存 `TextureHandle` + LRU（§8.3）。

### 5. 导出

| 格式 | 方案 | 说明 |
|---|---|---|
| HTML | pulldown-cmark 直出 + **白名单清洗** | S5-09；清洗规则继承原型 8 条实测用例 |
| Markdown 源码 | 直接写原文 | 无清洗需求 |
| 图片（PNG） | 正文栅格化 | 对应原型 `rasterize.ts`；v1.0 视工期决定 |
| PDF | **外置系统打印/导出**，不内嵌引擎 | 见 ADR-004 |

HTML 导出的清洗顺序固定为：**先拼 TOC（标题文本转义）→ 再整体清洗**。原型曾因「先清洗后拼 TOC」导致未转义片段进入产物（缺陷 2.4），本顺序为结构性修正。

## 影响范围

- S3-11：`Workspace` 聚合用 `FilePath` 值对象，不触碰 `std::fs`；
- S4-04：保存失败的错误语义（不清除脏标记）；
- S5-04 / S5-05 / S5-06：三个仓储实现；
- S5-09：清洗器与导出器；
- S5-11：资源加载器；
- S7-06：强杀恢复与原子保存中断演练。

## 复盘触发条件

- Windows 上因文件被占用导致 `rename` 频繁失败（阶段 07 实测结论）；
- 用户反馈配置目录位置不符合平台习惯。
