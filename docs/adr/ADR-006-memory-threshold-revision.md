# ADR-006 · `NFR-PERF-03` 内存阈值：按平台口径修订

- **状态**：已接受（2026-10-08，**需求方裁定**）
- **决策者**：需求方（裁定 OPT-007）
- **关联需求**：§1.2、§8.3（`NFR-PERF-03`）
- **关联任务**：S8-04
- **关联决策**：ADR-001（锁定 wgpu 后端，本 ADR 的前提）

## 背景

`NFR-PERF-03` 原写「空闲内存 ≤ 100 MB（目标 41–72 MB）」。阶段 08 实测（release，
Windows，空白文档静置 12s）：

| 口径 | 实测 | 原阈值 | 结论 |
|---|---|---|---|
| WorkingSet64（原判定口径） | 189.2 MB | ≤ 100 MB | ❌ 超标约 1.9 倍 |
| **Private Working Set** | **125.3 MB** | ≤ 100 MB | ❌ 超标 |

用「地板探针」（一个不引用本项目任何模块的**空 eframe + wgpu 窗口**，测完即删）
做归因后得到关键事实：**空窗口本身就要 124.4 MB（Private WS）**，
即「本项目全部自有代码 + 全部依赖数据」合计只有 **≈ 0.9 MB**。

也就是说：

- 这不是实现缺陷——§8.3 列的五项优化（Rope 唯一缓冲 / LayoutJob LRU 64 /
  Galley 缓存 / 纹理缓存 / 撤销栈上限）即便全部做到极致，能省的也只是这 0.9 MB
  里的一部分，**无可观测收益**；
- 阈值与基线**在数学上冲突**：ADR-001 锁定 wgpu 后端，而该后端的空窗口基线
  就已经超过 100 MB。**不推翻 ADR-001 就不可达**。

这是「需求假设与实测冲突」，按约定上报需求方裁定，不做自行假设。

## 决策

### 1. 阈值改为「按平台各自阈值」，`NFR-PERF-03` 不再给全局统一数字

原表述隐含「三个平台同一数字」，而三口径（Windows WorkingSet / macOS footprint /
Linux VmRSS）**本身就不可横向比较**——统一数字没有意义。修订为：

| 平台 | 判定口径 | 阈值 | 状态 |
|---|---|---|---|
| Windows | **Private Working Set** | **≤ 150 MB** | ✅ 实测 125.3 MB（余量 19.7 MB） |
| macOS | `footprint <pid>` | 待 Stage 09 真机补测后填入 | ⏳ |
| Linux | `/proc/<pid>/status` VmRSS | 待 Stage 09 真机补测后填入 | ⏳ |

### 2. Windows 判定口径从 WorkingSet64 改为 **Private Working Set**

理由（实测得来，见 `docs/metrics.md` §3.0.2 第 4 点）：WorkingSet 含共享页且受 OS
换页影响，**噪声可达 ±20 MB**——完整应用甚至测出过「低于空窗口探针」的结果
（189.2 vs 210.1 MB）。用它判定 1 MB 量级的优化收益会得出错误结论。
Private Working Set 只计入本进程私有页，是「应用自身占用」的正确口径。

WorkingSet64 仍照常记录，但**降级为参考值，不再作为达标判定依据**。

### 3. 阈值取 150 MB 而非贴近实测的 130 MB

留出约 20% 余量，容纳：语法集常驻、未来新增的内嵌资源、以及不同 Windows 版本
上 dx12 运行时的差异。若把阈值卡在 130 MB，等于把「基线漂移」变成常态化红灯，
门禁会失去信号价值。

## 后果

- **正面**：`NFR-PERF-03` 从「数学上不可达」变为「可达且有门禁意义」；
  S8-04 从「阻塞于需求冲突」转为**完成（结论为：不优化，记录归因）**。
- **负面 / 代价**：产品宣传口径从「内存 ≤ 100 MB」变为「≤ 150 MB（Windows）」，
  与阶段 01 的差异化定位表述有出入，需同步 §1.2 与对外材料。
- **待办**：macOS / Linux 阈值在 Stage 09 真机补测后填入本表；
  补测时**同样先做地板探针**，先分清「图形栈基线」与「自有代码」，再定阈值——
  否则会重演本次「阈值与基线冲突」。

## 被否决的选项

| 选项 | 否决理由 |
|---|---|
| 维持 ≤ 100 MB，记为未达标 | 阈值在 wgpu 后端下数学上不可达，长期红灯会让门禁失去信号价值，也会掩盖真实回归 |
| 换 / 加 glow 后端压低基线 | 需修订 ADR-001，并重新验证全部渲染与原型对齐用例，工作量与风险都远大于收益 |
