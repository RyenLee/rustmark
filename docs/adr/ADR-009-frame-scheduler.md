# ADR-009 · 帧循环定时任务统一走 `FrameScheduler`

- **状态**：已接受（2026-10-19）
- **决策者**：项目架构负责人
- **关联任务**：T11（优化任务清单 D1）
- **关联文档**：`src/app/frame/scheduler.rs` 模块文档、`tools/arch_check.rs`
  （预约唯一出口的机械守卫）、`docs/logs/问题记录1.txt`（问题 068）

## 背景

egui 是**事件驱动重绘**：没有输入、没有动画时根本不产生新帧。任何「等 X 毫秒后
再做一件事」的逻辑只要挂在帧循环里，用户一停手就永远等不到下一帧。

自动保存栽在这里（问题 068），当时的修法是在帧内手写
`ctx.request_repaint_after(剩余)`。但那是**逐处手写**的：每新增一个定时功能，
就要重新想一遍「谁算剩余时长」「谁负责预约」「0ms 怎么钳」。

核对代码后确认，问题 068 修好之后**又新增了三处同类逻辑、三处都漏了预约**：

| 位置 | 现象（编辑器失焦时） |
|---|---|
| `current_stats_for_status_bar` | 字数停在最后一次计算的值，永不刷新 |
| `HighlightPace`（高亮防抖） | 语法色**永久**停在无色状态 |
| `StatusBarUiState::message`（4s TTL） | 一条该消失的提示一直挂着 |

三者在编辑器**聚焦**时都被光标闪烁（每 0.5s 一次重绘）偶然兜住，所以从未被
用户报告——它们只表现为「偶尔慢半拍」。这是一个典型的「缺陷被另一个缺陷掩盖」。

## 决策

### 1. 抽象 = 登记表 + 唯一预约出口

`FrameScheduler` 不持有任何业务状态（自动保存计时器、`StatsPace`、`HighlightPace`、
`StatusMessage::expires_at` 的真值都在原处）。它只做两件事：

```text
帧首 begin(now_ms)          —— 清空上一帧的登记
帧内 arm(deadline, due_ms)  —— 声明「那一刻我需要一帧」（同键取更早）
帧末 flush(ctx)             —— 取最近到期点，换算成一次 request_repaint_after
```

调用点不再计算「剩余多少毫秒」，也不再能「算了却忘了预约」——因为算剩余的
动作本身已经不在调用点。这是本抽象唯一的牙齿。

### 2. `Deadline` 用 enum，不用字符串

字符串键拼错只在运行时表现为「另一个任务」；两个任务若共用同一个键会**静默
互相覆盖**，症状是「某个定时偶发不触发」，几乎无法归因。enum 让拼错编译不过。

### 3. 登记表每帧重算，不跨帧持久化

到期点是本帧依据当前状态**算出**的，不是需要维护的调度状态。持久化会引入
「文档关了、消息换了，旧到期点还在表里」的陈旧登记，还得再配一套失效逻辑——
而每帧重算的成本只是几次饱和减法。

`begin` 无条件清表：某帧没有 `flush`（无头测试只画不调度）时，残留登记在这里
丢掉，而不是留到下一帧变成幽灵预约。

### 4. 唯一出口用 `check-arch` 机械守卫

`request_repaint_after` 在 `src/` 里只允许出现在 `app/frame/scheduler.rs`。
文本扫描规则加在 `tools/arch_check.rs`（与分层依赖检查同一处），`build.rs` 与
`cargo run --bin check-arch` 都会跑。

理由：这条不变式**不产生编译错误、单测也未必覆盖**——谁在别处写一句直接预约，
测试全绿而「漏预约」的坑原样回来。与 ADR-008 里「写错不报错」的判据同源，
只是这里的兜底手段是机械扫描而非类型。

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| 让 `FrameScheduler` 持有全部定时状态（自己的 timer wheel） | 一个统一入口 | 真值在别处（计时器按文档、防抖按版本），必须双份维护并解决同步；等于把三套状态重写一遍 | 否决：抽象越界 |
| 提供 `schedule(closure, delay)` 回调式调度 | 用法直观 | 需要 `'static` 闭包与内部可变状态，与 `&mut EditorApp` 的帧内借用冲突；且回调里还要访问 `self` 的其他字段 | 否决：借用模型不允许 |
| 只写文档约定「记得自己预约」 | 零改动 | 历史上已漏三次，文档约定已被证伪 | 否决 |
| 本期方案：登记表 + 唯一出口 + 机械守卫 | 新增定时功能只需一行 `arm`；漏预约被 `check-arch` 拦住 | `begin`/`flush` 两个调用点必须留在 `EditorApp::ui` 的正确位置 | **采纳** |

## 后果

- **正面**：三处漏预约的缺陷被修复（编辑器失焦后字数会刷新、语法色会恢复、
  消息会消失）；新增定时功能的固定成本从「想三件事」降为「一行 `arm`」。
- **正面**：`flush` 在 `main_view::show` 之后，因此状态栏的统计防抖与消息 TTL
  也能登记——这两个的到期时刻只有绘制阶段才知道。
- **负面（诚实交代）**：`begin` / `flush` 仍是两个必须成对的调用点。它们被放在
  `EditorApp::ui` 的首尾，任何「提前 return」都会让 `flush` 跳过（当前实现没有
  提前 return）。这一点由「真实帧的 `repaint_delay`」测试兜住：只要某帧漏了
  `flush`，延迟会塌回 `Duration::MAX`。
- **负面**：`arm` 的正确性依赖调用点每帧都被执行。若某个定时功能改为「只在
  特定分支执行」，它的到期点会在其他帧被清掉。这是「每帧重算」的必然代价，
  替代方案（持久登记 + 显式 cancel）引入了更难查的陈旧登记，故不采纳。
