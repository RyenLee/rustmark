## 1. 阶段目标

在 egui 上实现**与原型视觉与交互对齐**的完整界面，并满足全部 P0 交互需求（FR-01~FR-06）。本阶段是唯一需要频繁人工视觉确认的阶段，按 Agent 流程文档 §8.4 采用「Agent 生成骨架 → 人工看效果 → 反馈修正」的 2–3 轮循环。

注意：表现层**只依赖 application 层**（§6.4），不直接引用 domain / infrastructure；UI 状态与业务状态严格分离。

### S6-04 增量高亮与 LayoutJob 缓存

- **描述**：仅重新构建变更行的 `LayoutJob`；`LayoutJob` 缓存 LRU 上限 64 项（§8.3）；大文件（> 500KB）仅高亮可视区（FR-06）。高亮通过 `MarkdownAppService::HighlightQuery` 获取 spans，表现层只做 spans → egui 样式的映射。**不直接调 syntect**。
- **前置依赖**：S6-03、S4-06
- **涉及文件**：`src/presentation/views/editor_view.rs`、`src/presentation/theme/mapper.rs`
- **验收标准**：单测/手工验证：单行编辑时仅该行重建（用计数器断言）；10KB 文档单次全文高亮 ≤ 10ms（`NFR-PERF-05`，记录基线）；1MB 文档滚动时可视区高亮不掉帧；缓存命中率记录到调试面板。
- **实现状态（2026-10-07）**：
  - ✅ 已实现并完成验证：全量单测 626 项全绿（新增 `tests/presentation/highlight_layout_test.rs` 21 条）/ `clippy --all-targets` 零业务告警 / `check-arch` 无分层违规。
  - ✅ **等价性**：`highlight_layout` 按行排版再 `egui::Galley::concat` 拼回的结果，与「单个整文档 `LayoutJob`」逐行一致（行数、每行字形数、`ends_with_newline`）。这条最关键——它若错了，光标/选区/双击选词会整体错位，而编译和运行都不会报错。
  - ✅ **计数器断言**：敲一个键重排 1 行；中间插入一行重排 1 行；全文替换只重排真正变化的那些行。
  - ✅ **命中率可见**：编辑区底部 readout 打印「共 N 行 · 重排 x · 复用 y · 行布局 z」（统一调试面板由 S6-11 收敛后迁入）。
  - ✅ **性能基线（NFR-PERF-05）**：10KB（13440 字节 / 841 行 / 12600 字形）整篇高亮 **2.3ms**（本机 debug 构建），远低于 10ms 预算。
  - ⚠️ **对 §8.3「LRU 上限 64」的实测偏离（重要）**：文档原设想定容 LRU 64 项，但 `TextEdit` 的 `layouter` 每帧要求**整篇**结果，访问模式是「按文档顺序请求全部行」——**任何容量小于行数的缓存，面对全顺序扫描命中率都是 0**。实测 65 行文档会雪崩：第 0 行被挤出后 miss→插入→挤掉第 1 行→第 1 行 miss→…，退化为每次击键全量重排，S6-04 等于白做。故改为**显式保留上一版全部行 + 前后缀差分 + 中间段逐行配对**。内存并不翻倍：`Galley::concat` 内部克隆的是 `Arc<Row>`，行数据（glyph / mesh）与本就保留的整篇 Galley **共享**，每行只多一个薄外壳。`repeated_line_hits_stay_cached`（故意用 65 行越过曾经的容量）与 `scattered_edits_only_reshape_changed_lines` 两条用例专用于钉死这两个回归。
  - ⚠️ **span 分配改用双指针**：逐行 `iter().filter(...)` 取 span 是 O(行数 × span数)，改为按起点排序后单趟归并，降到 O(行数 + span数)。
  - ⚠️ **> 500KB 降级为「停止 span 着色」而非「仅高亮可视区」**：文档写的是后者，但 `layouter` 接口拿不到滚动位置（viewport），无法实现；可视区虚拟化留待阶段 07。
  - ⏳ **1MB 文档滚动不掉帧**待真机走查（当前基线：553KB / 500 行冷启动 25ms，之后编辑为增量）。

#### 实现状态（2026-10-07）

**交付**：查找替换面板（`find_replace_view.rs`，原为 1 行桩）+ 浮层渲染通路（`overlays.rs`，新建）+ 30 条功能用例 + 3 条应用层顺序回归用例。

##### 跨文档策略（验收要求「明确定义并写进文档」）

**保留查询与选项，重置命中选中与命中列表。** 理由：用户常在多个文件里找同一个词，但命中位置属于旧文档，带过去会跳到错误位置。`keep_query_across_documents = false` 时连查询与选项一并清空。

命中列表必须**清空**而非保留——它的字节偏移属于旧文档。这是「重置选中」之外必须做的第二件事：只重置 `current` 而留着 `finder`，点「下一个」仍会按旧偏移跳。

##### 修掉的 4 个缺陷（全部零报错、界面正常、功能无反应）

1. **`Ctrl+H` 完全静默失效**（同 S6-07 三个 stub 的形态）：`Overlay::opened_by()` 里 `Find => UiAction::Find`，`Replace` 不是任何浮层的 `opened_by`，于是 `openable_overlay(Replace)` 返回 `None`，`execute` 落进 `_ => {}`。修法：新增 `Overlay::also_opened_by()` 表登记附加开启动作，`openable_overlay` 取两张表的并集。新增 `overlay_opening_tables_are_mutually_inverse` 锁住互逆性。
2. **根本没有浮层渲染通路**：`main_view` 从不画任何 overlay，`Overlay` 的视图全是 1 行桩。新建 `overlays::show` + `has_view` + `PENDING_VIEWS`（S6-11 待办清单），由 `every_overlay_outside_the_pending_list_has_a_view` 钉住「漏了就红」。
3. **查找面板被当成模态**：`is_modal()` 曾是「栈非空」，会让分发器拦下所有开浮层动作，用户发现「按了 Ctrl+F 之后整个编辑器都不能用了」。新增 `Overlay::is_modal()`，Find 是唯一非模态浮层（对齐原型：它浮在编辑区右上角，编辑区仍可编辑）。
4. **正则在查找框聚焦时劫持全局快捷键**：用户在查找框里按 `Ctrl+B`，文档里的字被加粗了。`collect_actions` 里加让位规则（`Esc` 永远放行）。

##### 修掉的 2 个数据/引擎缺陷

5. **`Aa` 开关对正则完全无效**：`Regex` 编译时不带 `case_sensitive`，`Node::Char` / `class_matches` 恒按大小写敏感比较。`c.t` 在 `cat CAT Cat` 上只命中 1 处而非 3 处。修法：`case_sensitive` 编译期固化进 `Regex`（选项变更本来就重新编译），比较走 `chars_eq`；字符类**逐端折叠**而非整体折叠（`[A-z]` 折叠后端点会互换，方向反了导致什么都不匹配）。
6. **`DocumentRegistry` 用 `HashMap` 迭代，标签顺序不确定**：`ids()` 直接 `keys().collect()`，而标签条按它显示、`Alt+2` 按它取下标。后果是 `GotoTab2` 可能「切到自己」（表现为快捷键毫无反应）、「下一个标签」在两个文档间来回跳。**这是跨文档查找用例失败的真正根因**——不是查找逻辑错，是切换压根没发生。修法：注册表加 `order: Vec<DocumentId>` 维护插入顺序，重复插入不改变位置（内容更新 ≠ 新开标签）。

##### 引擎层加固

- **`[z-a]` 端点反序在编译期报错**。此前它会编译成「永远匹配不到任何字符」的类，用户看到的是「正则没写错却一个都搜不到」，比明确报错难查一个数量级。
- **收敛 `record_scan` → `rescan`**：前者接收已编译好的 `Finder`、后者自己扫，是同一件事的两种写法。两份入口必然出现「调用方用了旧的那份、忘了更新 `finder` 字段」的分歧——这正是 S6-07 在 `editor_ops` 与 `EditingService` 之间踩过的坑。`Finder` 直接存进状态，`rescan` 成唯一写入口。
- **「全部替换」只产生一个撤销点**（一次 `replace_range(0..len)`）。逐条替换会让用户按一次 Ctrl+Z 只撤一处。断言写成「撤**一次**就全回去」而不是「连撤到栈空痕迹消失」——后者两种实现都成立，抓不到。
- **无限增生警告**：`aa` 替换 `a` 会指数膨胀，每一遍都提示「已替换 N 处」看起来完全正常。反向（`a` 替换 `aa`）是收敛的，**不**报警。

##### 三标签的数据来源刻意不同

| 标签 | 数据来源 | 判据 |
|---|---|---|
| 文件 | **已装载快照**（`WorkspaceEntries`） | `scan_tree` 是递归 `read_dir`（上限 5000 条），每帧做一次会在窗口最小化时也狂读磁盘，且顺序随文件系统返回序变化导致树抖动 |
| 大纲 | **每帧现算** | 只解析已缓存的块，代价可忽略；缓存它会让「文件改了但大纲还是旧的」 |
| 搜索 | **每帧现算 + 真扫盘** | 有 300 条命中上限兜底；同理不能缓存 |

判据一句话：**代价高且能被显式失效才缓存**（打开文件夹 / 文件操作后显式 `scan_workspace`）。故新增 `EditorApp::refresh_workspace()` 公开入口 + 侧栏「刷新」按钮——文件也会在本应用之外被改（别的编辑器、git 拉取、构建产物被清理），没有刷新入口用户会看到「树里有这个文件但点开说文件不存在」。

##### 文件操作的三条安全底线

1. `create_file` 用 `OpenOptions::create_new(true)` 而非 `create`——后者会**静默截断**同名文件，用户「新建」撞上同名文件就会清空原内容且界面无异常。
2. `rename` 前显式检查目标存在——POSIX 的 `fs::rename` 会**静默覆盖**目标，Windows 直接失败；不统一则两端行为不一致且更难排查。
3. `remove` 对目录用 `fs::remove_dir`（非空即失败）而非 `remove_dir_all`——右键删一个目录就抹掉里面全部内容，几乎必然招致后悔。递归删除应是另一个**显式**动作（且带确认）。

**落盘顺序**：选「副本验规则 → 落盘 → 改真聚合」。排除另两种顺序：「先落盘再改聚合」会让规则拒绝时磁盘已被改；「先改聚合再落盘」会让落盘失败时聚合里多个不存在的条目。副本法的代价是一次 `Vec` 克隆，但这是**用户点击触发**而非每帧执行。

`InMemoryWorkspaceRepository` 的四个新方法语义**刻意与真实实现一致**——替身比真实实现宽松，测出来的绿是假的。

##### 树投影的三个边界

1. **顺序**：假定输入已按「目录在前、同层按名称」排好（`FsWorkspaceRepository` 保证），自行重排会破坏「重命名后位置不动」的预期。实际顺序是**深度优先**（本层目录 → 本层文件 → 逐个递归子目录），故 `readme.md` 会夹在 `docs` 和它的子项之间。
2. **深度**：按**路径分隔符个数**相对根计算，而非「数前面有多少个目录条目」——后者在条目列表不完整时（如跳过隐藏目录）会算错。
3. **折叠的目录自身仍要显示**：收起 `a/` 时 `a` 这行还在，只是子项不画。

`is_last` 需二次扫描标注（扁平列表里没有「是否最后一项」信息），条目上限 5000，代价可忽略。

##### 搜索高亮必须用字符坐标

搜索片段要交给 egui 排版，「一」在 UTF-8 里 3 字节，按字节切会落在字符中间（症状：整个片段不高亮，或高亮块里少半个字）。`locate_in_snippet` 返回 `(usize, usize)` 字符下标。

大纲跳转与搜索跳转共用 `goto_byte_offset`——两条路径对「跳过去之后要做什么」的理解必须一致（选中 + 滚动），否则用户会发现「大纲跳转不选中、搜索跳转选中」进而怀疑其中一个坏了。行号 → 字节偏移复用 `scroll_sync::line_start_offsets`，自己换算一遍会与 `scroll_to_offset` 各算各的，迟早漂移。

##### 标题升降级走领域规则

大纲底部明确提示「标题级别的调整请在编辑区用 Ctrl+[ / Ctrl+]」，走 `FormatCommand` 的 `PromoteHeading` / `DemoteHeading`，与工具栏按钮、快捷键三入口共用。大纲内横向拖拽调层级是原型做法，若另起一套必然与它们漂移。

##### 焦点只在「刚切过来」时给

切到搜索标签时把焦点交给搜索框（egui 0.33 没有文本回读接口，`ctx.debug_text` 是写入方向，控件状态是唯一稳定的外部可观察量；这同时是正确的 a11y）。但判据必须是「**上一帧画过的**标签不是搜索」而非「当前没有焦点」：编辑区同样没有焦点，若无差别请求，用户在搜索结果里点开一个文件后焦点会被侧栏抢回去。

实现上不能只比较本帧开头读到的 `sidebar_tab`——标签值可能在本帧绘制**之前**就被改掉（快捷键、命令面板、测试直接赋值），那样 `previous` 恒等于当前值，切换永远检测不到。故 `SidebarUiState::drawn_tab` 由视图在画完后回写。

egui 0.33 没有 `ContextMenu`（只有给菜单栏用的 `MenuButton`），且菜单需「记住作用于哪一行」，故 `context_menu_path` 放状态而非 egui popup id。

##### 本节修掉的三个真实缺陷

均**不报错、界面看起来正常**，只是功能没反应或悄悄改错东西——这类缺陷只能靠探针与变异测试抓到，读代码看不出来。

1. **目录被标成 `EntryKind::File`**（`fs_workspace_repository.rs`）。`collect` 里 `dirs` 与 `files` 分开收集但共用循环体，循环体内硬编码 `EntryKind::File`，导致 `FileEntryView.is_directory` 恒为 `false`，**文件树根本无法建层级**。探针实测：含 1 个子目录的工作区扫描出 0 个目录。

   更值得记的是：`workspace_repository_test.rs` 里有一条用例**把这个缺陷锁进了测试**——它先断言 `names == ["m_dir", "alpha.md", "zebra.md"]`（`m_dir` 是目录、排第一），紧接着又断言 `entries[0].kind() == EntryKind::File`。两条断言自相矛盾，说明当时有人注意到了顺序异常却用错误的断言把它「修绿」了。**测试与实现互相印证错误，比没有测试更危险。**

2. **`retarget_heading` 选区平移错误导致标题升降级改错行**（`domain/document/services.rs`）。「剥旧前缀 → 加新前缀」两步之间用固定步长左移选区，两处都错：① 光标**恰好落在改动区间起点**时那里并没有字节消失（只是后面内容顶上来了），却被左移 → 第二步作用到**上一行**；② `toggle_line_prefix` 是**逐行切换**的，多行选区里 `## A` 缩短 3 字节、`正文` 却**变长** 3 字节，净值为 0，固定步长根本无法表达。单行文档之所以正常，是 `start.saturating_sub(0, 3) == 0` 侥幸掩盖了 bug。

   **修法不是把平移算对，而是删掉两步**：改成对每行做**一次替换**（读出该行已有的 `#` 数量 → 换成目标层级）。这同时消掉第二个缺陷——「剥前缀」用的是切换语义，对没有该前缀的正文行会**加上**它，两步之后正文变成 `# ## 正文`，而 `demote_heading` 的文档明确承诺「已经是正文的行保持原样」。

   多行选区里哪些行该改，判据是「**该行本来就是标题**」或「**该行是光标所在行**」：光标行总是要改（用户把光标放在正文上点提升就是想把它变成标题，这条不能被上一条误伤）；选区里其余的正文行不改（「标题 + 下面的正文段落」一起选中再点降级，用户期待标题降级、段落仍是段落）。

   顺带删掉了 `splice`（两步写法专用）并让 `Edit` 回到只覆盖改动行的区间（与 `toggle_line_prefix` / `indent_lines` 一致），撤销栈里不再存整篇。

3. **切到搜索标签时搜索框拿不到焦点**（`sidebar_view.rs`）。`export_view` / `settings_view` 都有这段逻辑，侧栏漏了，用户切过来还要再点一次才输得进字，会以为这个标签坏了。

##### 统计口径：不是精度差异，是数量级差异

原型的 `countWords` 是**中日韩按字、西文按词**，而原实现用 `split_whitespace().count()`。差别不是「差一点」：一整段没有空格的中文会被算成 **1 个词**，800 字的中文稿显示「8 字」。这正是验收标准点名「口径一致」的原因。

重写后逐项对齐原型：字数（中日韩按字 + 西文按词）、字符数（含/不含空白）、行数、段落数（空行分隔的非空块）、标题数（`#`~`######`）、围栏代码块数、链接数（**不含**图片）、图片数、任务项（`- [x]` / `* [ ]` / `+ [X]`，`-` 与 `[` 之间允许空白）、阅读时长。

三处需要判断的地方：

1. **围栏内的内容整体跳过**。代码示例里写 `## 不是标题` / `- [ ] 不是任务` 不该被计入，否则统计数字会随文档里的示例代码漂移。
2. **图片不计入链接数**（原型口径）。否则一张图会在「链接」和「图片」两栏各数一次。
3. **阅读时长下限为 1 分钟**（原型 `max(1, round(words/300))`）。一篇只有几个字的草稿显示「约 0 分钟」比「约 1 分钟」更让人困惑。

**与原型正则的一处有意偏离**：原型的 `/[A-Za-z0-9_'-]+/g` 会把**孤立的连字符**算成一个词——`- [ ] todo` 里的 `-` 命中一次、`[x]` 里的 `x` 命中一次，于是 5 词的任务清单显示「8 字」。本实现加一条判据：单词必须**至少含一个字母数字**才算。破折号、星号、方括号都是 Markdown 的结构符号而非词，把它们计进字数只会让「列表越多字数越虚高」。这条偏离由 `lone_hyphens_are_not_words` 钉死，免得后人对齐口径时「顺手改回正则」而无人察觉。

##### 状态栏的三个设计决定

**编码项可显示但不可点。** 原型能点 `UTF-8 ⇄ GBK` 切换。本应用现在的**读取**已支持多种编码（见下），但**写入仍然只有 UTF-8**。给一个能点的切换开关等于**承诺一个做不到的功能**：用户切到 GBK 后保存，文件仍是 UTF-8，而状态栏说自己是 GBK。故 `TextEncoding` 保留在枚举里但只有一个变体，且显示的是**保存格式**（UTF-8）——不显示"读到了什么"，因为那会与保存结果不符。不可点的项用弱化色画，且**悬停仍给提示**（说明「为什么点了没反应」）。

> **读取侧的编码支持（2026-10-08 补）**：`infrastructure/persistence/encoding.rs` 已实现分级探测
> —— UTF-8 BOM → UTF-16 BOM → 裸 UTF-8 → GBK 兜底，GBK 用内嵌的 47 KB 映射表解码（零新增依赖）。
> 因此**打开 GBK 文件不再乱码**。但保存时一律写为 UTF-8（含 BOM 与否跟随原文件），
> 即"打开 GBK → 保存"会**隐式转码为 UTF-8**。这对只看内容的用户无损，
> 但若在意文件编码本身（如需要交给只认 GBK 的旧工具），请注意这一点。
> 完整的双向编码支持（按原编码写回）与状态栏显示真实编码，均属后续工作。
>
> **【已被取代 · 2026-10-09】** 本节对该项的结论（`TextEncoding` 保留但只有一个变体、显示的是「保存格式 UTF-8」、不可点）**已在 v1.1 **V11-03** 中被推翻**：共享内核新增纯展示型 `TextEncoding`（多变体），基础设施探测的编码经 `DocumentSnapshot::encoding` 上报、应用层旁路表暴露，状态栏每帧同步**显示文档实际编码名**（`UTF-8` / `UTF-8 BOM` / `UTF-16 LE·BE` / `GBK` / `GB18030`），未落盘文档显示 `—`（不谎称 UTF-8）。写回原编码亦已支持（见 `docs/archive/stage-reports/p1p2-implementation-log.md` 的「保存写回原编码」）。原文保留以记录当时的取舍思路，**当前实际状态以 V11-03 为准**（见 `docs/v1.1-backlog.md` V11-03、`docs/PROGRESS.md` §1.1.1）。

**消息占左端，固定项位置不变。** 用户是**扫**状态栏的，字数忽然从第三格跳到第一格会让眼睛找不到。消息出现在左端空白处，固定项整体右推，消失后复位。消息带**到期时刻**（4 秒）而不是等下一个错误覆盖：不消失 → 「已保存」一直挂着；被覆盖 → 连续两次操作只看得见最后一次，两个都不对。

**千分位分隔。** 四位以上不加分隔符要数位数（`字数 12345`）。

##### 行号与列号：两个独立的坐标系错误

**列号必须按**字符**计。** 一个汉字在 UTF-8 里 3 字节，按字节算「你好」第二个字之前会显示「列 4」——用户数着自己的光标只会数出「2」。原型的 `posToLineCol` 用 JS 字符串 `slice`，对 BMP 内的汉字天然等价于字符列。

**光标可能落在非字符边界。** `EditorUiState::clamp_to` 只按**长度**夹紧，而程序化设值（大纲跳转、测试、`TextEdit` 回调）能给出任意字节偏移。直接切片会 panic，而本项目 `panic = "abort"` —— 一次 panic 就是**窗口直接消失**。`floor_char_boundary` 下取整（不用上取整：那会让列号比实际**大**，用户会发现「明明在第 3 个字，状态栏说第 4 列」；差一格且偏小比崩掉好）。

##### 欢迎页取代了「启动即建空白文档」

原型用**路由**表达：`/` 是 `WelcomeView`、`/editor` 是 `WorkbenchView`——欢迎页是**首屏**，不是「标签全关时的兜底」。

这推翻了 S6-01 的一条设计。那时的判断是「窗口刚打开时 `active_doc` 是 `None`，用户面对的是一块点了没反应的灰板」，故 `EditorApp::new` 里调 `with_initial_document()` 建一份「未命名」空白文档。有了欢迎页之后那份空白文档就是多余的：它让 `active_doc` 立刻是 `Some`，**欢迎页永远不显示**；而且用户不会想编辑一份叫「未命名」的空白文件，只会在里面打字然后忘了保存。

两者只能选一个，选欢迎页。`editor_view` 仍**每帧**调 `ensure_document()` 兜底，保证「一旦离开欢迎页，编辑区永远有一页可编辑」。删掉 `with_initial_document` 方法本身——留着它只会让人以为还能用。

`close_document` 刻意**不**关最后一个标签（「永远至少一页可编辑」是硬约束），所以欢迎页需要一条独立通路 `close_all_documents()`（`force = true` 逐个关）。标签条上关掉最后一个标签的「×」时走这条路径。

「打开文件 / 打开文件夹」只登记 `PendingDialog` 而不直接调 `DialogPort`——后者同步阻塞，不能在 `update()` 里调（S5-08 已写明）。

##### 本节修掉的三个真实缺陷

1. **`line_start_offsets` 末元素与末行行首重复**（`scroll_sync.rs`）。文本以 `\n` 结尾时 `split('\n')` 拆出的末行本身就是空行、其行首恰好等于 `text.len()`，哨兵再补一次就成了重复元素。而 `line_of_offset` 用 `partition_point`：

   ```text
   starts = [0, 3, 6, 6]   offset = 6 → 命中 4 个 → 行号 3
   starts = [0, 3, 6]      offset = 6 → 命中 3 个 → 行号 2  ✅
   ```

   三行文档算出「第 4 行」，跳转与滚动同步都落到不存在的行上。哨兵本身仍需要（滚动到底部时反查行号可能等于行数，没有哨兵会越界而 `panic = "abort"` 直接终止进程），只是**不与末行行首重复**。

2. **`UiAction::Save` / `NewDocument` / `OpenDocument` 从未接线**（`app/frame.rs`）。三个动作都在 `UiAction` 枚举里、都有默认快捷键，但 `execute` 的 `match` 里没有对应分支，全部落进 `_ => {}` 兜底。`Ctrl+S` / `Ctrl+N` / `Ctrl+O` 静默失效——**不报错、界面正常、只是没反应**。状态栏的「未保存 → 点击保存」与欢迎页的三个主操作都依赖它们，故必须接线，不能让各视图各写一套保存逻辑。

   未命名文档按 `Ctrl+S` **不弹错误**而是转成「另存为」请求：用户按 `Ctrl+S` 的意图是「把这份东西存下来」，弹一个「需先指定保存路径」等于把「另存为」这一步的工作推给用户（而 `Ctrl+Shift+S` 就能做到同一件事）。

3. **统计口径三处不符**（`compute_stats`）：字数按空白切分、阅读时长 `/200.0` 不取整、`StatsView` 缺 6 个原型字段。见上节。

#### 一、分层收口：`presentation/state` 子层规则

`tools/arch_check.rs` 新增 `PRESENTATION_STATE_FORBIDDEN`，`layer_of` 识别 `presentation/state` 子层，违规报错附「业务数据来自 DTO」的说明。

**必须说清的事实**：这条规则在当前名单下**不新增任何拦截**。`PRESENTATION_FORBIDDEN` 已禁掉整个 `crate::domain`，而 `crate::domain::document` 是它的**前缀**——凡匹配子层的路径必然也匹配父层。我最初想造一个「父层允许、子层禁止」的对照物，**造不出来**（试过 `std::fs`，它在表现层根本合法，两边都不报 0 条）。

它买到的两样东西：

1. 报错文案指明「是 UI State 这一层」并附上准则，读者不会当成随手定的规则去加 `arch-allow`；
2. 若将来 `PRESENTATION_FORBIDDEN` 被放宽，这条独立规则仍在原地。

**过程中修掉的真实缺陷**：子层第一版写成**替换**父层名单（`PRESENTATION_STATE_FORBIDDEN.to_vec()`），那样 `state/` 就不再受 `crate::infrastructure` 等父层禁令约束——那是**放宽**而非收紧，与意图相反。由 `the_state_subdirectory_still_obeys_the_parent_layer_rules` 抓到，已改为叠加。

`has_view` 同时从**枚举式**判定改为「不在 `PENDING_VIEWS` 里」：枚举式（`matches!(overlay, A | B | C)`）在 `Overlay` 新增成员时不会报错，只会让新成员**静默返回 false**——而「有开启动作却没视图」正是 S6-07 那种静默失效的形态。

#### 二、命令面板

| 文件 | 职责 |
|---|---|

**关键实现选择：检索逻辑刻意不重写。** `ActionTable::search`（子序列匹配、标签 100 / 关键词 50 权重、命中字符坐标）**早在 S6-09 就已实现并测透**（7 条用例）。两套检索一旦分叉，就会出现「命令面板搜得到、菜单搜不到」——而「三入口同源」正是 S6-09 反复强调的根治目标（原型缺陷 B-02 / B-08 的结构性解法）。本模块只管视图状态，命令清单取自 `ActionTable`。

因此「面板能搜到的 == 菜单能看到的」是**结构性成立**的，由 `the_palette_and_the_menu_read_the_same_action_table` 逐字核对（显示名与快捷键都要一致）。

**修掉的真实缺陷（`registry.rs`，S6-09 遗留）**：`search` 把**关键词命中的坐标**原样塞进 `ScoredAction.hits`，而该字段文档写的是「命中字符在 `label` 中的下标」。对 `Bold`：label「加粗」（2 字）匹配失败 → 落到 keywords「bold」→ `hits = [0,1,2,3]`，**坐标 3 越界**。UI 按它切标签会切出乱码。已改为关键词命中时 `hits` 置空（`score` 保留 50 供排序）。

S6-09 的 7 条测试**没断言 keywords 命中的 hits 值**，所以这个越界坐标从未被测到过——修复零回归，但也说明那条防线一直是空的。

#### 三处刻意的原型偏差

| 偏差 | 理由 |
|---|---|
| **不移植 `disabled`**（无脏文档时「全部保存」灰显） | 与现有菜单行为一致。菜单无 `disabled`，面板单独搞一套会造成「同一动作菜单能点、面板不能点」的新不一致 |
| **不收录原型 `Alt+1..9` 标签跳转** | 动作表里没有这 9 个动作，补它们是**新功能**，超出 S6-12 范围。收录动作表现有的全部动作，才满足验收标准 |
| **分组名不参与匹配** | 原型搜 `label + keywords + group`，搜「格式」会命中一堆无关条目。`ActionTable::search` 是已验收资产，为面板扩范围等于推翻一条已通过的验收。用例 `group_names_are_not_searchable` 把这个偏差钉住 |

#### 模态（背景不可交互）

原型的 `aria-modal="true"` + `Tab` 焦点陷阱在 egui 里无对应语义。本项目的等价物是 `DialogUiState::is_modal`：模态浮层打开时 `collect_actions` 调 `set_modal(true)`，分发器不再吐出动作。`CommandPalette` 属模态（`Find` 是唯一非模态——原型允许边看边改），由 `the_palette_is_modal_unlike_the_find_panel` 钉住。

**焦点归还机制已移除（更正）**：S6-12 留下的 `focus_return_id` / `set_focus_return` / `take_focus_return` 与 `frame.rs::overlay_focus_id` 是一套**空转的半套机制**——写死的 `"main_view.overlay_focus_sink"` 标识从未在任何视图注册，`take_focus_return` 也从未被调用，故移除行为与移除前完全一致（原本就不生效）。模态浮层打开时的背景不可交互仍由 `is_modal` 保证；焦点收尾交给 egui 默认行为。

## 4. 技术方案要点

- **egui 二次封装**：需求 §10 指出 egui API 不稳定（0.33.3 锁定 + 关键 API 二次封装）。表现层对 egui 的直接调用收敛在 `widgets/` 与 `theme/mapper.rs`，视图层只用封装后的组件，降低未来升级成本。
- **三入口一致性**：工具栏按钮、快捷键、命令面板必须共用同一张动作表（S6-07 与 S6-09 的验收核心），这是原型「四处真相」缺陷的结构性根治。


- **UI 不持有业务真值**：编辑区显示的文本来自 `DocumentView.content`，任何编辑都发 Command 走 Service 回写，UI State 只保存光标与滚动，避免双写不一致。
- **IME 隔离层**：S6-03 把文本输入抽象为「输入源」接口，若 egui 方案不达标可换 `cosmic-text` 而不影响上层。
