## 1. 功能概述

编辑区是主窗口三栏布局中的左侧面板（`SidePanel::left("rustmark.editor")`，宽度随分割比例可拖拽），承担 Markdown 源码的查看与修改职责。其技术实现的核心特征可概括为五点：

1. **编辑表面复用 egui `TextEdit`**：不自绘编辑器，直接使用 egui 0.33 的多行 `TextEdit`（`code_editor()` 模式）作为编辑表面，原生获得 IME 支持（候选词窗口跟随光标、组合期不污染已提交文本）——这是 FR-05 要求的「不自己造输入法」的务实兑现。
2. **领域是内容的单一真相**：`TextEdit` 绑定的 `editor_text` 只是领域文档内容的 UI 副本；每次编辑以最小差异（`diff_replace`）换算成 `ReplaceRangeCommand` 写回领域，随后由 `refresh_text()` 保证副本与领域永不漂移。
3. **撤销权威在领域**：egui `TextEdit` 自带撤销栈，但本项目通过「领域改文后清空 egui 撤销栈 + Ctrl+Z 路由到领域」的双重机制，使撤销/重做只走领域栈。
4. **语法高亮分层处理**：应用层负责「要不要算」（防抖 + 缓存），表现层负责「怎么排」（逐行增量排版 + 两层缓存），编辑区只消费 `SpanView` DTO，不直接调用 syntect。
5. **纯函数编辑逻辑**：缩进/反缩进/移动行/列表续行/括号配对等变换抽成不依赖 egui 与领域的纯函数，可无头单测，也为将来更换编辑表面预留了隔离层。

编辑区同时还是**双向滚动同步的主动方之一**（S6-06）：其滚动偏移经「像素 → 行号 → 字节偏移 → 块映射」两段式换算驱动预览区，细节见 `11-预览区技术实现.md` 与本文 §4.10。

### 2.3 单一真相与三份文本的关系

| 载体 | 角色 | 维护方式 |
|---|---|---|
| 领域 `Document`（Rope） | 内容唯一真相 + 撤销栈 + 修订号 | 只由命令修改（`ReplaceRangeCommand` 等） |
| `EditorApp::editor_text` | 绑给 `TextEdit` 的 UI 副本 | 领域命令后由 `refresh_text()` 整篇覆盖；输入帧由视图就地拼成一致终串 |
| `EditorUiState::{cursor, anchor}` | 光标 / 选区（字节偏移） | 每帧从 egui 回读（字符索引换算）；领域改写编辑时由 `pending_cursor` 回设 |

三者漂移的后果是「用户敲了键界面却没反应」或「撤销后内容又回来了」，代码中以「`current_content()` 与 `editor_bound_text()` 必须逐字节相等」作为可观测不变量（集成测试直接断言）。

### 3.1 帧渲染入口 `editor_view::show`

`show` 是编辑区每帧的唯一入口，函数体 324 行**明确禁止拆分**（内部提取 helper 属高风险动作，见文件头约定）。其步骤顺序即数据流：

1. `apply_pending_editor_state(&ctx)` —— 把上一帧领域编辑留下的「清撤销栈 / 重设光标」落到 egui 内部状态（必须在 `TextEdit::show` 之前，否则本帧光标不更新）；
2. `ensure_document()` —— 每帧兜底保证有活动文档（「永远至少一页可编辑」）；
3. 工具栏（`draw_editor_toolbar`，高度取 `metrics.editor_toolbar_height`，与预览区标题栏等高——两栏对齐的结构性保证）；
4. 行号栏宽度实测（等宽字体量最大行号位数，不写死 44pt）；
5. 预计算三类标记：语法高亮 spans（`HighlightQuery`，全文区间）、拼写错词区间（`SpellCheckQuery`）、查找命中（`FindMark`，来自 `FindReplaceUiState::finder`）；
6. 构造 `layouter` 闭包：**不借用 `app`**（预计算已取得 owned 数据），把唯一可变借用让给 `TextEdit`；闭包内完成「高亮排版 + 波浪线就地绘制」；
7. `TextEdit::multiline(&mut app.editor_text)` 装配并 `show`；
8. 光标/选区回读（egui 字符索引 → 字节偏移）；
9. 文本变更 → `diff_replace` → `transform_insert` → 就地拼终串 → `flush_edit`；
10. 右键拼写菜单；滚动偏移回写与几何量上报（`set_geometry(Side::Editor, …)`）。

### 3.2 状态容器 `EditorUiState`

只存**字节偏移**，不存文本、不存 Rope。光标放 UI 层而非领域层的理由：它不参与撤销语义（撤销一次输入不该把光标弹回三行之前），却必须随编辑更新——放错层会导致「撤销时光标乱跳」（原型缺陷 B-07）。关键不变量：

- `selection()` 始终返回归一化区间（用户可能从后往前拖选）；
- `clamp_to(len)` 在内容变化后夹紧光标与锚点——越界偏移会让 `TextBuffer::slice` panic，而 `panic = "abort"` 下 panic 即进程终止；
- `composing` 记录 IME 预编辑文本，`should_skip_snapshot()` 是 FR-05「组字期间不触发撤销快照」的实现点。

## 4. 核心处理流程

### 4.1 文本编辑回路（每按键一次）

```text
用户按键
  │
  ▼
egui TextEdit 就地修改 editor_text（含其内置撤销栈推进一步）
  │
  ▼  response.changed() 为真且 prev != editor_text
editor_ops::diff_replace(prev, new)          最长公共前缀/后缀 → 最小替换区间
  │  TextEdit { byte_start, byte_end, inserted, cursor_char, anchor_char }
  ▼
editor_ops::transform_insert(prev, &mut edit)  括号配对 / 列表续行 / 空项退出列表
  │  （返回 transformed：领域是否真的改写了这次编辑）
  ▼
就地拼出与领域一致的终串：editor_text = prev[..bs] + inserted + prev[be..]
  │  （省掉「从领域整篇回读」——那次回读每帧替换绑定字符串，
  │   会迫使 egui 重推光标/选区/撤销栈，表现为编辑区闪烁）
  ▼
EditorApp::flush_edit(edit, prev.len(), transformed)
  ├─ ReplaceRangeCommand { id, range, text } ──► 领域（写入 + 推进修订号 + 领域撤销栈）
  ├─ preview.mark_edited(now)                  预览防抖计时起点
  ├─ transformed ? pending_cursor = Some(..) : 不动 egui 光标
  └─ clear_undoer_next = true                  下一帧清 egui 内置撤销栈
  │
  ▼ 下一帧
apply_pending_editor_state：非 IME 组字期时
  ├─ TextEdit::load_state → clear_undoer → store
  └─ pending_cursor.take() → state.cursor.set_char_range(CCursorRange)
```

三个容易踩坑的实现要点：

1. **`flush_edit` 的钳制基准必须是 `domain_len`（旧文本长度）而非 `editor_text.len()`**。「回车退出列表」变换会把文本改短（拉起点删掉整个 `4. ` 标记），`byte_end` 相对旧文本可能大于新文本长度；按新长度钳制会把区间砍短，领域层只删掉半个标记（实测症状：`4. ` 残留成 `. `）。
2. **`transformed` 为 false 时不回设光标**。普通输入里 egui 自己的光标已落在正确位置，再写 `pending_cursor` 是纯粹多余的状态变更：既制造一次额外光标重算（闪烁），又可能撞上 IME 守卫导致光标失联（V11-14：连按回车只多出一个新行）。
3. **`response.changed()` 早退**。egui 每帧都要 `show`（UI 必须渲染），但 diff 计算只在真的改了文本时才做；用户停手后立刻跳过整个 diff 路径，大文档上每帧省掉一次 O(n) diff。

### 4.2 语法高亮链路

```text
editor_view::show（每帧）
  │  HighlightQuery { doc_id, range: 全文, lang: "markdown" }
  ▼
MarkdownAppService::highlight
  ├─ content.len() > 500KB ──► 返回空 spans（大文件降级，FR-06）
  ├─ HighlightPace::settled ──► 未静止（防抖期）返回空 spans（OPT-011 ①）
  ├─ HighlightCache 命中（文档+版本+语言+区间）──► 直接返回
  └─ SyntaxHighlighter::highlight_range ──► SpanView[] 写入缓存
  │
  ▼  spans（字节区间 + 样式字符串）
mapper::highlight_layout_with_find(ctx, theme, text, spans, wrap_width, find)
  ├─ 签名 = palette_signature(theme) + find_sig + colored + editor_metrics_signature
  ├─ WHOLE_CACHE 命中 ──► 直接返回整篇 Galley（空闲帧零开销）
  ├─ 与上一版行布局差分：公共前缀 → 公共后缀 → 中间段逐行配对，得到复用映射表
  ├─ 变更行：build_line_job（span 前景色 + 查找命中背景，边界吸附字符边界）→ 重新排版
  └─ Galley::concat 拼回整篇（sections 必须非空，DEF-05）
  │
  ▼
layouter 闭包返回 Galley；波浪线（spell_marks）就地绘制
```

防抖与缓存的两处关键设计：

- **高亮防抖时间戳打在「版本变化被发现的那一帧」**（`HighlightPace::settled`）。若打在「算完了」的时刻，计时起点会被每次计算刷新，防抖退化成节流——连续打字照样每帧重算，10KB 文档白付 56ms/帧。首次见某篇文档不防抖（打开/切换文档应立刻有颜色）。
- **行布局缓存不是定容 LRU，而是「显式保留上一版全部行」**。`TextEdit` 的 layouter 每帧要整篇结果，访问模式是按文档顺序请求全部行——任何容量小于行数的缓存面对全顺序扫描命中率都是 0（第 0 行被挤出后 miss→插入→挤掉第 1 行→雪崩）。保留上一版全部行后，内存并不翻倍：`Galley::concat` 内部克隆的是 `Arc<Row>`，行数据与本就保留的整篇 Galley 共享。

### 4.3 IME 组合期守卫状态机

`apply_pending_editor_state` 是编辑区最精密的一段逻辑，守护两个动作（回设光标、清撤销栈）不与 egui 的 IME 处理打架。背景：egui 0.33 的 `Preedit` 会把预编辑串**真实写进文本缓冲区**，并靠「组合锚点 ↔ 预编辑串尾」选区删旧换新；`Commit` 还会校验锚点是否仍在组合起点，不在则整个提交被静默忽略。而回设的折叠光标（secondary = 串尾）恰好打掉这个选区。

```text
每帧扫描 ctx 输入事件，四分类：
  Preedit ──► 组合确实在进行：ime_composing = true，续窗 IME_GUARD_MS(800ms)
  Commit / Disabled ──► 组合收尾：立即解冻（Commit 不得续期！）
  Enabled ──► 仅表示 egui 的 ime_enabled 已置真：egui_ime_armed = true，短窗 IME_ARM_MS(50ms)
  无 IME 事件且 armed 到期 ──► 判定「并无组合在进行」：
      ├─ 补发 egui::Event::Ime(Disabled) 复位 egui 的 ime_enabled
      └─ 抹平本帧 Enter 的 repeat（remove_ime_incompatible_events 在 show 内部
         按当帧 ime_enabled 剔除 repeat 按键，晚一步的 Disabled 救不回它）
  守卫窗内到达裸按键/裸文本 ──► 组合已作废：补发空 Commit("") 折叠光标、
      解除两扇守卫（否则 TextEdit 的 delete_selected 会吃掉已落进领域的预编辑串）
```

三层设计约束（均有实测缺陷背书）：

1. **冻结必须有界**。粘性标志（只有 `Commit`/`Disabled` 才清）在真实环境会卡死——winit 的 `Disabled` 只在失焦时发，切输入法/直接关候选窗都可能收不到。标志一旦永久为 true，`pending_cursor` 的消费被冻结而 `flush_edit` 每次按键又覆写它，光标永远停在旧位置，之后每次回车插到同一处（V11-14 症状：「连按回车只多出一个新行」）。
2. **两个窗口分开取值**。`IME_GUARD_MS`(800ms) 管自己的守卫——宁长勿短，覆盖用户斟酌候选词的击键间隔；`IME_ARM_MS`(50ms) 管复位 egui 的 `ime_enabled`——宁短勿长，过长等于冻结回车。
3. **`Commit` 立即解冻而非续期**。旧实现把 `Commit` 与 `Preedit` 同列为「组合进行中」并续窗 800ms，导致提交后立刻在列表项上回车时，`pending_cursor`（"2. " 之后）被冻结、egui 光标仍停在 `\n` 之后，再回车把 `\n` 插到 `2. ` 前面、transform 又续一个标记——「行号正常递增，光标附近却不见新行」的根因。

### 4.4 撤销 / 重做 / 格式动作

- **撤销/重做**：`Ctrl+Z`/`Ctrl+Y` 由快捷键分发器路由到 `EditorApp::undo_edit/redo_edit` → 领域 `UndoCommand`/`RedoCommand` → `sync_cursor_from_domain()`（先 `refresh_text()` 回读，再按领域光标/选区设 `pending_cursor` 与 UI 状态）→ `clear_undoer_next`。egui 内置栈被彻底架空。
- **格式动作**：工具栏按钮、快捷键、命令面板三入口全部汇聚到 `EditorApp::execute(UiAction)`，再由 `apply_format` 映射到 `FormatKind`，`run_format` 调用应用层 `FormatCommand`。「三入口一致」不是靠三处都写对，而是按构造成立（菜单项本身也是遍历 `MenuGroup × UiAction::ALL` 生成的）。
- **缩进/反缩进**：`Indent`/`Outdent` 动作直接走应用层 `format` 用例（S6-07 收敛），缩进规则归领域 `EditingService` 所有——`editor_ops` 曾自带的双份实现已删除，避免双真相。

### 4.5 拼写检查与建议菜单

```text
帧首（开启时）：SpellCheckQuery { doc_id, enabled } ──► spell_check
     关闭时返回空集、不查缓存不重算（关掉的代价为零）；失败一律降级为空集
     │
     ▼  SpellMark[]（错词字节区间）
layouter 闭包内：squiggles_for(galley, text, marks, ZERO) 换算字节→像素
     └─ 跨行错词按 galley.rows 拆成每行一段，相邻片段错开相位
     paint_squiggles：closed_line 逐段连出锯齿，贴在基线下 1px

右键：spell_menu_for(app, galley, galley_pos, pointer)
     Galley::cursor_from_pos → 字符索引 → char_to_byte → 字节偏移
     word_bounds_at 扩到整词 ──► 该词必须已被判错（只给标红的词提建议）
     spell_suggestions(SpellSuggestQuery { offset, limit: 5 })
     ──► SpellSuggestMenu（跨帧存在：egui 的 Area 是即时模式，不存状态就没有「下一帧还开着」）
绘制：Area::fixed_pos(菜单屏幕坐标) + 陈旧检测（区间内容变了就关重来）
点击建议：replace_spelling(start, end, &replacement) ──► ReplaceRangeCommand
```

### 4.6 查找命中高亮

`FindReplaceUiState::finder`（手写匹配器：字面量 + 大小写 + 全字 + 迷你正则，三开关正交）产出命中列表；帧首换算成 `FindMark[]`（文档字节坐标 + `current` 标记）传给排版层，由 `build_line_job` 把 `find_bg`/`find_current_bg` 背景烘焙进逐行 Galley。命中集变化通过 `find_sig`（FNV 折叠）并入两层缓存键——否则会残留旧高亮。查找框焦点由 `FIND_INPUT_ID` 常量统一（视图绑定与「快捷键是否让位」共用同一值，写成两处字面量会让让位逻辑静默失效）。

### 4.7 行号栏绘制

- **宽度**：按最大行号位数在等宽字体下实测（`layout_no_wrap("0".repeat(digits))`），万行文档不挤掉最后一位、十行文档不留空白；
- **位置**：行号不是独立控件，而是用**本帧真实排版的行顶表**（`mapper::line_tops`，来自逐行 Galley 高度累加，含折行）配合 `galley_pos` 换算屏幕坐标，锚定在行带垂直中心——与字体度量无关，中文回退字体再高也不重叠；
- **只画可视区内的行号**（`clip_rect` 裁剪），大文档滚动时无谓 `format!` 每一行会拖慢滚动；
- **行距等距的结构保障**：编辑区所有内容共用同一字号与同一**显式行高**（`editor_font_size × editor_line_height`）——`TextFormat::line_height` 一旦给出，epaint 不再按字体度量算行高，`tops[i+1] - tops[i]` 恒为常数（除非该行折行）。

### 4.8 滚动同步（编辑区侧）

编辑区每帧把真实滚动偏移回写 `app.editor.scroll_y = out.state.offset.y`，并上报几何量；`scroll_sync::apply` 在两侧都画完后执行一次：

```text
observe(now, editor_y, preview_y) ──► 单一主动方判定（100ms 抑制窗口过滤回声）
  │
  ▼ 主动方为 Editor
drive_preview：
  editor.scroll_y ──line_at_y(tops)──► 行号 ──line_start_offsets──► 字节偏移
  MapScrollQuery { Editor { offset } } ──► ScrollTarget::Preview { block_id, ratio }
  offset_for_block(rects, id, ratio) ──► 预览区目标 y（块顶 + 块内比例插值 − 8pt 余量）
  │
  ▼ 文本变更引发的「把光标滚进视口」必须声明为程序性位移
editor_view 第 5 步：note_programmatic_scroll(Side::Editor, now_ms)
  （否则同步把它当用户手势，一帧一次把预览区拉到映射位置 —— 两栏同时在动即「界面闪烁」）
```

状态与几何分离：`scroll_sync_state.rs` 只有数据与状态转移（可独立单测抑制窗口），`scroll_sync.rs` 只有像素换算（纯函数）。

### 4.9 编辑区字体装配（每帧一次比对）

```text
EditorApp::ensure_editor_fonts(ctx)          # update 开头 + 启动各调一次
  │
  ├─ selected = settings().theme.font_family # 持久化配置（权威来源）
  ├─ selected == installed_font_family ? ──是──► 直接返回（零开销）
  └─ 否 ──► infrastructure::fonts::font_definitions(Some(selected))
              │  ① 发现可选字体（内置三款打头 + 项目 fonts/ + 系统等宽，仅存在性检查）
              │  ② 读字节登记进 font_data（内置资产走 include_bytes! 零拷贝）
              │  ③ 追加数学兜底 → 系统 CJK → 内置 CJK 子集（链序：西文 → 数学 → 系统中文 → 内置中文）
              │  ④ 选中字体置顶进内置 Monospace 族（先去重再插入）
              ▼
           ctx.set_fonts(...) + 记下 installed_font_family
```

三条约束：

- **没变就不重装**：`set_fonts` 会触发 egui 整体重建字体图集（一次可见卡顿），故每帧只做一次字符串比对；
- **启动仍赶在首帧前**：创建闭包里「先构造应用（持有配置）→ 再装字体」，eframe 画首帧前会走完该闭包，用户上次选的字体从第一帧就生效，不出现「先用默认字体画一帧再跳变」；
- **缓存随之失效**：字体族在 `editor_metrics_signature` 里，换字体即整篇重排（否则 Galley 复用旧字形，见 §6 设计决策 16）。

## 5. 接口设计

### 5.1 表现层内部接口

| 接口 | 签名要点 | 说明 |
|---|---|---|
| `editor_view::show` | `(&mut EditorApp, &mut Ui)` | 帧入口；facade 不拆 |
| `editor_ops::diff_replace` | `(&str, &str) -> Option<TextEdit>` | 最小替换；无变化返回 `None` |
| `editor_ops::transform_insert` | `(&str, &mut TextEdit) -> bool` | 叠加自动变换；返回是否改写 |
| `editor_ops::char_to_byte` / `byte_to_char` | `(&str, usize) -> usize` | 坐标系换算；越界夹到末尾 |
| `mapper::highlight_layout_with_find` | `(ctx, theme, text, spans, wrap_width, find)` | 逐行增量排版入口 |
| `mapper::line_tops` | `(theme, text) -> Option<Vec<f32>>` | 行顶表；拿不到返回 `None`（下一帧自愈，绝不猜行高） |
| `mapper::squiggles_for` | `(galley, text, marks, origin) -> Vec<Squiggle>` | 纯函数几何 |

### 5.2 表现层 → 应用层接口（查询）

```rust
HighlightQuery { doc_id, range: TextRange, lang: Option<String> }   // 编辑区全文高亮
HighlightSnippetQuery { text: String, lang: Option<String> }        // 预览区代码块片段高亮
SpellCheckQuery { doc_id, enabled: bool }                           // enabled=false 直接空集
SpellSuggestQuery { doc_id, offset: usize, limit: usize }           // 只按 offset 定位，服务自行扩词
```

### 5.3 表现层 → 应用层接口（命令，经 `EditorApp` 中转）

```rust
ReplaceRangeCommand { id, range: TextRange, text: String }  // 一切文本修改的唯一出口
FormatCommand { id, kind: FormatKind, range, indent_unit }  // 缩进/反缩进/加粗/列表/标题…
UndoCommand / RedoCommand { id }                            // 领域撤销权威
```

`EditorApp` 侧的关键方法（`app/frame/editor.rs`）：`flush_edit`（输入回路）、`replace_source`（预览区回写，不动光标）、`replace_all`（整篇变换）、`refresh_text`（领域 → 副本 + 预览防抖打戳）、`sync_cursor_from_domain`、`run_format`、`move_line`、`cursor_line_col` / `selection_line_col`（状态栏，字符列口径）。

### 5.4 跨层 DTO

```rust
SpanView { range: RangeView, style: String }  // 字节区间 + 稳定样式字符串（21 种）
```

`style` 是字符串而非领域枚举——表现层不得依赖 domain（`check-arch` 硬约束），`StyleMapper::format` 是这些字符串的唯一解释处，未知样式退回正文色而不报错。

## 6. 关键设计说明

| # | 设计决策 | 理由与权衡 |
|---|---|---|
| 1 | 复用 egui `TextEdit` 而非自绘编辑器 | 原生 IME 支持是 FR-05 最高风险项；代价是其自带撤销栈与 Tab 语义与「领域是真相」冲突，用「清撤销栈 + 快捷键路由」化解。风险预案（cosmic-text 自绘）由 `editor_ops` 纯函数层兜底 |
| 2 | `editor_text` 是副本而非第二真值 | 原型 `editor.ts` 的双写不一致是致命缺陷 B-05；副本每次命令后由 `refresh_text()` 覆盖，输入帧就地拼成一致终串，二者永不漂移 |
| 3 | 坐标系双轨制：UI 字符索引 / 领域字节偏移 | egui 只认字符索引，领域只认字节偏移；`İ`、emoji、组合字符让两者不等，直接用字节切文本会 panic（`panic = "abort"` 下即窗口消失） |
| 4 | 撤销权威在领域 + 清空 egui 撤销栈 | 两套撤销栈打架会「撤销一步回到三帧前」；`clear_undoer_next` 在 IME 组字期冻结（组合帧依赖未碰的选区） |
| 5 | IME 三层守卫（有界窗 + 补发 Disabled + 裸键废弃组合） | 每个机制都对应一个实测缺陷：粘性标志卡死（V11-14）、`ime_enabled` 卡死吞回车（repeat 剔除）、`Commit` 续期导致标记堆积（2026-10-11 复报）、armed 到期帧抹平 repeat（2026-10-12 暴力扫描） |
| 6 | 高亮防抖下沉应用层，时间戳打在「版本变化被发现」时 | 打字期不上色（连续打字语法色暂时消失，停手 150ms 恢复）换帧率：10KB 文档击键帧从 67.9ms 降到 ≈0 |
| 7 | 行布局「保留上一版全部行」而非定容 LRU | 全顺序扫描访问模式下任何有界缓存命中率都是 0（雪崩效应）；`Arc<Row>` 共享使内存不翻倍 |
| 8 | 显式行高（字号 × 行高系数） | 不给行高时 epaint 按字体度量算，中文回退字体行高更高 → 行距不等距 → 行号栏、滚动同步、光标命中全部错位；给出后结构性消除 |
| 9 | 标题在编辑区只换色不换字号 | 源码视图每行行高必须一致；层级用 `syn_heading` 色表达（VS Code / Typora 源码模式同款） |
| 10 | 换行由 `desired_width` + layouter 覆盖 `INFINITY` 实现 | egui 0.33 的 `TextEdit` 没有 `.wrap(bool)`；`wrap_width = desired_width.min(available)` 即使 `INFINITY` 也被有限宽钳制，故在 layouter 内按开关显式覆盖 |
| 11 | 一切外部坐标先吸附字符边界（`clamp_to_char_boundaries` / `floor_char_boundary`） | span / 查找命中 / 程序化光标都可能落在多字节字符中间；吸附后最坏少一段色，绝不崩（DEF-04 / crash-20261011005255） |
| 12 | 拼写检查不防抖、失败降级为空集 | 已是 O(词长) 哈希查找且「开着就应立刻反映输入」；让它把编辑器卡住或弹错是本末倒置 |
| 13 | 编辑区工具栏按作用分组、贴编辑区顶部 | 与全局顶栏分层：「下拉 = 应用级命令入口，分组按钮 = 编辑区内容命令」；等高标题栏保证两栏内容区从同一水平线起 |
| 14 | 查找输入框 Id 常量共享 | 视图绑定与「快捷键让位」判据必须同源，否则「查找框里按 Ctrl+B 又把文档加粗了」且无任何报错 |
| 15 | 编辑区字体**不建自建族**，把选中字体置顶进内置 `Monospace` 族 | 自建族（`FontFamily::Name("editor")`）要求每一处排版前该族都已注册；而 egui 对未注册的 `FontFamily::Name` 是 **panic**（epaint `fonts.rs:808`），本项目 `panic = "abort"`——任何「先排版、后装配」的路径（无头测试、将来的新入口）都会让窗口消失。实测：改自建族后 6 条既有单测以 panic 形式暴露，遂废弃。置顶进内置族则 `FontId::monospace` 永远有绑定，零 panic 风险；代价是选择连带影响一切等宽界面（预览代码块、命令面板、差异对比），与 VS Code「编辑器字体」同语义 |
| 16 | 字体族纳入 `editor_metrics_signature` 缓存键 | 不纳入时，换字体后逐行 Galley 会因「行内容没变」被整批复用——表现为「换了字体但编辑区没变」，与字号同源；纳入后一次重排即恢复 |
