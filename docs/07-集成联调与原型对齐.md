## 3. 任务清单

### S7-01 端到端用例集（P0 全覆盖）

- **描述**：按需求文档 §3.1 的 P0 条目 + §3.2 的 FR-01~FR-06，编写端到端用例：新建 → 编辑（含中文输入）→ 语法高亮 → 撤销/重做 → 查找替换（正则）→ 保存 → 重开内容一致 → 导出 HTML → 分屏预览滚动同步 → 多标签切换 → 关闭脏文档提示。每条用例含：前置条件、操作步骤、预期结果、判定方式（自动/手工）。
- **前置依赖**：S6-01 ~ S6-11
- **涉及文件**：`docs/e2e-cases.md`、`tests/e2e/**`
- **验收标准**：用例数 ≥ 30，P0 功能 100% 覆盖（对照 `REQUIREMENTS.md` 逐条打勾）；可自动化部分（领域与应用层可测的）进入 `cargo test`，UI 部分进入手工清单并标注；用例在干净环境（全新配置目录）下从零执行通过。

### S7-02 行为对齐矩阵（原型 ↔ Rust）

- **描述**：逐项比对原型与 Rust 实现的可观测行为：① 渲染差异（`marked` GFM vs pulldown-cmark：表格对齐、脚注编号、任务列表 checkbox、HTML 内联标签、自动链接）；② 语法高亮差异（highlight.js 语言别名 vs syntect 语法名：20 种语言逐一比对 token 与配色）；③ 数值口径差异（字数统计、阅读时长、任务完成度、行数、字符数含/不含空格）；④ 交互默认值（防抖 150ms、撤销合并窗口 400ms、搜索命中上限 50/300、最近文件上限 20、图片内联上限）。
- **前置依赖**：S5-02、S5-03、S6-05、S6-11
- **涉及文件**：`docs/prototype-alignment.md`、`tests/integration/alignment_test.rs`
- **验收标准**：矩阵 ≥ 40 行，每行标注「一致 / 差异（理由） / 已处置」；统计口径类差异必须给出明确取舍（以 Rust 实现为准并同步更新 README，或修正 Rust 实现）；20 种语言的高亮对齐表完成，无法映射的语言记录替代方案。

### S7-04 大文件与边界场景验证

- **描述**：构造 1MB Markdown 样本（含长表格、大量代码块、100+ 图片引用、超长单行），验证：可编辑不卡顿（§4.1）、> 500KB 触发降级（FR-06）、滚动与查找可用、保存耗时可接受。另测边界：空文档、仅 BOM、单文件 10 万行、深度嵌套列表/引用、未闭合代码围栏、超长 URL、非法 UTF-8 字节（**不崩溃且不丢上下文**——lossy 兜底，见 Q1 决策）。
- **前置依赖**：S5-01、S5-04、S6-04
- **涉及文件**：`tests/data/golden/large_1mb.md`、`docs/manual-qa-*.md`
- **验收标准**：1MB 文件：打开耗时、首屏可交互耗时、滚动帧率、全文查找耗时四项数字记录；> 500KB 降级确实触发（断言仅可视区高亮）；8 类边界输入全部不崩溃且给出可读错误；非法 UTF-8 文件**不崩溃且不丢上下文**（lossy 兜底，非报错——Q1 已定：维持现状）。

## 4. 技术方案要点

- **自动化与手工分工**：能脱离 GUI 断言的（解析、高亮、统计口径、撤销、sanitize、原子保存）全部自动化；必须看屏幕的（布局、DPI、字体、IME、打印）进手工清单并保留截图/录屏。
- **差异必须留痕**：原型与 Rust 实现不可能 100% 一致（渲染引擎不同），关键是把差异**显式记录并获评审同意**，而不是默默不一致。
- **失败不绕过**：本阶段发现的缺陷回到对应阶段任务修复（例如撤销语义问题回 S3-08），禁止在本阶段写 UI 层补丁——这正是原型"补丁式修复"积累技术债的教训。

## 5. 风险与注意事项

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| 渲染差异过多 | 中 | pulldown-cmark 与 marked 的 GFM 细节差异导致预览与原型不一致 | S7-02 逐项记录；以「符合 CommonMark/GFM 规范」为最终判据，不以原型为绝对标准 |
| 手工回归耗时 | 中 | 三平台 × 15 项耗时超预期 | 优先 Windows + macOS（主要用户群），Linux 用 CI 容器补基础项；清单可增量复用 |
| 大文件样本偏理想 | 中 | 自造样本不能反映真实长文 | 用真实技术文档（如长 README、书籍章节）补一份样本 |
| 强杀恢复难自动化 | 中 | 需要跨进程操作 | 拆成「草稿写入」+「启动恢复」两个可自动化部分，中间的强杀用脚本完成 |
| 平台差异处置不一致 | 低 | 各平台行为漂移 | S7-05 输出统一处置表，写入 `docs/` 作为后续版本基线 |
