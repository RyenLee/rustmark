## 1. 功能概述

预览区是主窗口三栏布局中的右侧面板（`CentralPanel`，吃掉编辑区与分割条之外的全部宽度），把 Markdown 源码渲染成排版视图。其技术实现的核心特征可概括为六点：

1. **只消费 DTO，不解析 Markdown**：数据流是「领域解析（pulldown）→ `RenderedBlock` → `BlockView`（DTO）→ egui 控件」。本模块不碰 domain，换解析器或换渲染后端都不应波及这里。
2. **缓存键 + 防抖控制重解析**（FR-01）：换文档、主题/字号变化立即重建；同一份文档的内容变化等 150ms 防抖窗口（合并连续击键）。
3. **按块类型分发渲染器**：标题 / 段落 / 引用 / 代码块 / 列表 / 任务列表 / 表格 / 图片 / 分割线 / 脚注 / 定义列表 / 公式 / 图表 / 目录 / 原始块，共 15 种 `kind` 字符串。
4. **三种可点击交互**：任务列表复选框（点击回写源码，走与编辑区同源的 `ReplaceRangeCommand`，可撤销）、代码块复制按钮、Mermaid 图表内链接（新标签页打开）。正文 Markdown 链接**不**假装可点击——`BlockView` 只有纯文本，URL 未下沉到 DTO。
5. **内置公式与图表引擎**：LaTeX 子集与 Mermaid 子集各自以「解析 → 排版（纯函数）→ 绘制」三段管线渲染；子集外的写法不猜，回退到带失败原因的源码卡。
6. **失败永不 panic**：坏图降级为占位、渲染失败退化为一行提示、span 边界吸附字符边界——`panic = "abort"` 下任何 panic 都是进程终止，而预览区的输入全是外部内容驱动的。

预览区同时是**双向滚动同步的另一半**（S6-06）：既作为目标方被编辑区驱动，也通过视口顶部命中块反驱编辑区，并响应标题/目录的点击跳转。

## 2. 整体架构

### 2.1 数据流总览

```text
              ┌─────────────────────────── 领域层 ───────────────────────────┐
              │  MarkdownParser（pulldown-cmark 适配器）                       │
              │    "…源码…" ──► RenderedBlock[]（块 ID / 类型 / 源码区间 / 行内片段）│
              └────────────────────────────┬──────────────────────────────────┘
                                           │ view_mapper::to_block_view
              ┌─────────────────────────── 应用层 ───────────────────────────┐
              │  MarkdownAppService::render_preview(RenderPreviewQuery)      │
              │    fetch 内容+版本 ─► >500KB 截断降级 ─► parse_or_cache       │
              │    ─► RenderedView { blocks: Vec<BlockView>, version, truncated }│
              └────────────────────────────┬──────────────────────────────────┘
                                           │ BlockView（kind 字符串 + 可选字段）
              ┌─────────────────────────── 表现层 ───────────────────────────┐
              │  preview_view::show                                          │
              │    sync_document ─► 缓存键+防抖判定 ─► render_preview          │
              │    blocks ─► draw_block 按 kind 分发 ─► 各块渲染器 ─► egui     │
              │    每块 rect 采集 ─► BlockRect[]（滚动同步换算依据）            │
              └───────────────────────────────────────────────────────────────┘
```

### 2.2 缓存层次

| 层次 | 位置 | 键 | 失效条件 |
|---|---|---|---|
| 渲染缓存（解析产物） | 应用层 `RenderCache`（`Arc<Mutex>`，容量 16） | `文档 ID → (版本号, RenderedBlock[])` | 版本号变化；主题切换主动 `invalidate` |
| 预览 UI 缓存（块序列） | `PreviewUiState::blocks` | `PreviewCacheKey { doc_id, content_version, palette, font_size_q }` | 键变即重渲染（见 §4.2） |
| 块矩形 | `PreviewUiState::rects` | 无（每帧重新采集） | 立即模式下块位置随宽度/字号/图片解码变化，跨帧复用比不缓存更危险 |
| 图片纹理 | `preview_view` 线程局部表 | 图片引用字符串（URL/路径/data URI） | 不淘汰（条目数有界于用户内容；同一张图跨文档只解码一次） |

### 2.3 预览区在应用中的位置

```text
main_view::render_split
 ├─ SidePanel::left("rustmark.editor")  ──► editor_view::show
 ├─ SidePanel::left("rustmark.divider")     分割条
 └─ CentralPanel（内边距与 SidePanel 对齐：两栏顶栏/内容区不错位）
     └─ preview_view::show ◄── 本文主题
         ├─ pane_header            与编辑区工具栏等高的标题栏
         ├─ render_preview         条件性重解析
         └─ ScrollArea::both()     逐块渲染 + rect 采集
     之后：scroll_sync::apply      两侧画完执行一次同步
```

### 3.2 DTO 契约 `BlockView`

预览区与领域之间唯一的跨层数据结构。刻意**不用枚举**：`kind` 字符串 + 可选字段表达同样的信息，既能承载表格/列表/定义列表结构，又不把领域类型引进表现层（`check-arch` 硬约束）。

```rust
BlockView {
    id: u64,                       // 单次解析内唯一（id_salt 与滚动同步都用它）
    kind: String,                  // "heading" | "paragraph" | "code_block" | "table"
                                    // | "list" | "task_list" | "quote" | "image"
                                    // | "rule" | "footnote" | "definition_list"
                                    // | "math" | "diagram" | "toc" | "raw:<marker>"
    content: String,               // 块纯文本
    level / lang / ordered / items / table / alt / url / marker
    display / diagram / label / definitions
    spans: Vec<SpanView>,          // 块内行内样式（区间相对 content）
}
```

`ListItemView` 携带 `start/end`（源码字节区间，任务回写用）、`depth`（层级，pulldown 吃掉缩进后层级只存在于这个字段）、`ordinal`（有序编号，不从 1 重数）、`checked`、`spans`；`TableView` 携带 `header/rows/aligns` 与按列补齐的 `header_spans/rows_spans`。

## 4. 核心处理流程

### 4.1 帧渲染管线

```text
preview_view::show(app, ui)
 1. pane_header                    与编辑区工具栏等高的标题栏（两栏内容区对齐）
 2. 无活动文档 ──► "没有打开的文档" 返回
 3. app.preview.sync_document(doc_id)        换文档即重置（唯一入口，见 §6-3）
 4. version = 注册表 content_and_revision 的修订号
 5. key = PreviewCacheKey::new(doc_id, version, theme)
    want = preview.should_render(key, now_ms, false)
 6. if first || want：
      render_preview(RenderPreviewQuery { doc_id, version })
        Ok ─► blocks = view.blocks；set_degraded(view.truncated)
        Err ─► "预览渲染失败：{e}" 返回（编辑区照常可用）
      record_render(key, now_ms)
 7. degraded ─► "文档过大，预览已降级"（FR-06：明确告知而非静默空白）
 8. blocks = std::mem::take(&mut app.preview.blocks)   零拷贝取出，渲染后还回
    （渲染期间任务项回写要 &mut app，借用检查器不允许同时持有两者）
 9. headings = blocks 里 kind=="heading" 现场收集（目录用，存副本必然过期）
10. ScrollArea::both().auto_shrink([false,false]).show：
      for block in blocks：
        ui.scope_builder(id_salt(block.id)) ─► draw_block(app, ui, theme, block, headings)
        rects.push(BlockRect { id, top: rect.top()-base, bottom: rect.bottom()-base })
        ui.add_space(space_xs)           块间距（scroll_sync 换算假定此值）
11. blocks 还回；rects / scroll_y 回写；set_geometry(Side::Preview, …)
```

### 4.2 重解析判定（缓存键 + 防抖）

```text
PreviewCacheKey { doc_id, content_version, palette[4], font_size_q }
  │
  ▼ should_render(key, now, force)
  force                              ──► true
  last_key 为 None（首帧/重置后）      ──► true
  key.document_changed()              ──► true（立即，不走防抖）
  key.appearance_changed()            ──► true（立即；否则切主题顿一下才变）
  key.content_changed()               ──► now - last_edit_at_ms >= 150ms（防抖）
  其余                                ──► false
```

四个构成要素各有一次缺陷背书：**doc_id 必须进键**（版本号是每份文档各自的计数器，两份未编辑文档版本号天然相同，只比版本号会让切 tab 后预览一直停在第一份文档）；**palette 进键**（只用内容版本则改字号/主题不重建，设置看起来无效）；**font_size_q 整数化**（避免浮点抖动导致每次都判定「变了」）；**换文档不走防抖**（切 tab 是显式导航而非连续击键，压进防抖窗口观感正是「预览没跟着 tab 走」）。

防抖计时起点（`mark_edited`）必须打在**编辑**时而非**渲染完成**时：打在渲染完成时，计时起点会被每次渲染刷新，持续输入时退化成「每 150ms 重解析一次」的**节流**——实测连续输入 20 字符（1.2s）重解析 7 次，远超验收上限 2 次。

### 4.3 块分发

`draw_block` 按 `block.kind` 字符串 match 到 15 个渲染器；表格的结构化字段缺失（理论上不该发生）时退回段落纯文本，「总比空白好」。每个块经 `ui.scope_builder(UiBuilder::new().id_salt(block.id), …)` 包裹——`ui.scope` 产出的子 `Ui` 的 `ui.id()` 在同一父级下完全相同，而标题是唯一带 `Sense::click()` 的内联文本，不给 `id_salt` 会让第二个起的标题全部撞 id，egui 画出红框与「First/Second use of widget ID」警告（2026-10-10 实测）。

### 4.4 行内富文本排版（`inline.rs`）

```text
render_inline_text(ui, theme, content, spans, Typography{size, line_height, base_style}, sense, wrap_width)
  │
  ├─ spans 为空 ──► 整段纯文本一个 section（退化为普通 label 的等价路径）
  ├─ spans 非空 ──► 逐片段：
  │     clamp_to_char_boundaries 吸附越界/非字符边界区间（防 panic）
  │     片段间空隙用 base 格式补上；收尾补上最后一段
  │     style=="math"      ─► strip_math_delimiters（剥 $ 分隔符，语法不是内容）
  │     style=="footnote_ref" ─► footnote_ref_mark（[^1] 换成标号 1）
  │     task_done 是叠加在行内样式之上的装饰（勾选不抹掉用户原本写的粗体）
  └─ layout_job(job) ─► allocate_space ─► painter.galley ─► ui.interact(rect, id.with("rinline"), sense)
```

`LayoutJob` 而非「一段一个 `ui.label`」：逐段铺控件会让折行只发生在段与段之间；`LayoutJob` 把整行交给 epaint，折行、行高、对齐统一处理。字号与行高打包成 `Typography` 传递——两者必须成对（行高一旦给出，epaint 就不再按字体度量算行高），避免把行高错配给另一个字号。预览区刻意**不复用** `StyleMapper::format`（那个取编辑区字号与行高，会让预览字号跟随编辑区设置漂移）。

### 4.5 GFM 表格（`table.rs`）

两步布局，替代 `egui::Grid`（其列宽来自 sizing pass 的「愿意收缩到的最小宽度」，表头短正文长的表会被压成六七行）：

1. **测量**：每列取「表头 + 全部行」中最宽单元格的**单行**宽度（`layout_no_wrap`，与渲染同字体，故精确）；
2. **分配**：`table_column_distribution(natural, available)` 纯函数——
   - 放得下：每列拿「自然宽 + 内边距」，富余按内容占比摊满面板（视觉权重与内容长度一致）；
   - 放不下：每列先保底 `TABLE_MIN_COL_W(64pt)`，剩余预算按内容占比分配（长列拿大头）；
   - 窗口极窄连保底都给不起：宁可溢出也不把内容挤没。

绘制层自绘网格：列间竖线**在整行画完之后统一补**（各行高度不等，顺手画会得到长短不齐的短线）、每行底线、表头底色（深色主题里加粗几乎与正文同色，底色让表头可辨）。行距置 0（否则竖线在行交界处断开成虚线），纵向留白由单元格 `pad_y` 提供。

### 4.6 任务列表回写（`list.rs`）

```text
用户点击复选框（item.checked 翻转）
  │
  ▼ toggle_task(app, item, checked)
task_marker_offset(editor_text, item.start, item.end)
  在项的源码区间内找首个 "[ ]" / "[x]"（windows(3) 逐字节扫描，标记是 ASCII）
  只认首个：改错位置的代价远大于不生效；区间超界按长度裁剪（下一帧解析自愈）
  │
  ▼
EditorApp::replace_source(from, from+3, "[x]" | "[ ]")
  ReplaceRangeCommand（与编辑区完全同源）
  ──► 领域：内容改写 + 推进版本号 + 进领域撤销栈（可撤销）
  ──► refresh_text：编辑区副本同步 + 预览防抖打戳（下一帧重解析）
  不移动光标、不设 pending（用户焦点在预览区，编辑区光标应保持原位）
```

「预览勾上了、源码没变」的两处真相漂移由此被结构性排除。

### 4.7 图片加载与纹理缓存（`media.rs` + facade）

```text
draw_image(block)
  url 为空 ──► "图片地址为空：{alt}"
  max_w = min(面板可用宽, IMAGE_MAX_W 620pt)
  image_entry(ui, app, url)
    IMAGE_CACHE 命中 ──► 直接返回
    app.services.assets.load(url, base_dir=document_dir())
      Err（加载失败）──┐
      Ok ─► decode     ─┤─► ImageEntry { texture: None, error: Some(msg) }
        Err（解码失败）──┘      （统一成占位，不弹窗、不 panic）
        Ok ─► load_texture("preview-image:{url}") + 原始尺寸
    写入缓存（键 = 引用字符串：同一张图跨文档只解码一次；有界，不设淘汰上限）
  │
  ▼
  Some(texture) ─► 等比缩放到面板宽内，egui::Image
  None           ─► 固定高 96pt 占位框 + 失败原因（warning 色）
```

**占位高度固定是滚动同步的关键不变量**（FR-02）：若坏图/未就绪的图高度为 0，解码完成那一帧整页高度突变、其后所有块矩形整体下移，而滚动同步用的正是这些矩形——一次解码就让预览「跳位」。预留固定高度后，块布局与加载结果无关。解码失败一律 `Err` 不 panic：`panic = "abort"` 下坏图会直接终止进程，而图片解码是外部输入驱动的（损坏的 PNG、伪装成 PNG 的文本）。

### 4.8 公式与图表（`embedded.rs` + `math/` + `mermaid/`）

```text
draw_math(block)：math::layout(content, size, display, measure)
  Ok  ─► 行内公式跟随基线不套框；块级公式进源码卡式外框（带"公式"标签与复制按钮）
  Err ─► draw_unrendered_source：源码 + 类型标注 + 失败原因（"未能排版：{reason}"）
         （只显示源码不说原因，用户会去查自己的语法——而多半是编辑器不支持）

draw_diagram(block)：mermaid::layout(content, preview_font_size, measure)
  Ok  ─► 分层布局（Sugiyama：最长路径分层 → barycenter 排序 → 定位 → 正交走线）
         paint(graph) + click_targets() 命中区换算（与 paint 完全相同的缩放+平移）：
           ui.interact(screen_rect, ("mhot", i), click) ─► open_url(new_tab)
  Err ─► draw_unrendered_source（子集外图种：subgraph / stateDiagram / pie …）
```

两个内置引擎共享同一架构：**解析 → 排版（纯函数）→ 绘制**，度量通过 `&dyn Fn(&str, f32) -> f32` 注入，不碰 `egui::Painter`——于是「分数比分母高」「B 必须在 A 右边」「有环也不会卡死」这类排版规则都能在无头环境断言。为什么不塞 KaTeX/MathJax/resvg：前两者是 JS（eframe 没有 JS 运行时，内嵌浏览器控件体积 +100MB 量级），resvg 带 C 依赖且 `panic = "abort"` 下第三方库的任何 `unwrap` 都是进程终止。遇到子集外写法**不猜**——半张图画出来比不画更难排查，用户会先怀疑自己的语法。

### 4.9 目录 / 脚注 / 定义列表（`toc.rs`）

- **目录**：条目由**本帧块序列**现场收集（标题随编辑增删，存副本必然过期），按层级缩进，点击 `request_click(block.id)` 跳编辑区；文档无标题时显示「（文档里还没有标题）」。
- **脚注**：标签（`[1]`）与正文**并排但分开展示**——标签拼进 content 会参与搜索命中与字数统计，只画 content 又会出现没有编号的孤立句子。
- **定义列表**：术语加粗 + 释义缩进在术语下方并画短竖线连缀；不套项目符号（`• 术语: 定义` 会与普通无序列表混同，且从属关系被横向拉平）。

### 4.10 滚动同步（预览区侧）与点击跳转

```text
scroll_sync::apply(app, now_ms)（每帧、两侧都画完后）
  driver = sync.observe(now, editor.scroll_y, preview.scroll_y)   单一主动方 + 100ms 抑制窗口
  click = sync.take_click()                                       标题/目录点击（离散事件，优先）
  enabled = sync.enabled && preview_visible && !focus_mode && !degraded
  │
  ├─ click：drive_editor(app, Some(block_id)) ─► 记录 drive(Side::Preview)
  ├─ driver == Editor：drive_preview(app)（见 10-编辑区文档 §4.8）
  └─ driver == Preview：drive_editor(app, None)
        block_at_offset(rects, preview.scroll_y + HIT_BIAS 2pt)  ─► 视口顶部命中块
        MapScrollQuery { Preview { block_id } } ─► ScrollTarget::Editor { offset = 块源码起点 }
        line_of_offset(starts, offset) ─► line_tops[line] ─► editor.scroll_y = clamp(y - 8pt)
```

设计要点：

- **块映射 + 块内插值，而非按比例同步**。比例同步在高度分布不均时失效（前半段代码行矮、后半段图片块高，预览会停在完全无关的段落），直接违反验收「误差 ≤ 1 块」。
- **抑制窗口用时间而非比对写入值**。目标偏移会被 `ScrollArea` 夹紧（滚到底写 9999 实际落在 812），回声与写入值不等会被误判成用户手势，立刻反向驱动——抖动复现。
- **块矩形每帧重新采集**。立即模式下块的 y 随面板宽度、字号、图片解码结果变化；大图片刚解码完成那一帧若用上一帧矩形，会直接跳错块。
- **点击跳转不走抑制窗口**。用户点一下就该跳，等 100ms 反而像卡顿。

## 6. 关键设计说明

| # | 设计决策 | 理由与权衡 |
|---|---|---|
| 1 | 预览区不解析 Markdown、不依赖 domain | 数据流止于 `BlockView` DTO；换解析器或渲染后端不波及渲染层（文件头声明的边界） |
| 2 | `BlockView` 用 kind 字符串 + 可选字段而非枚举 | 承载表格/列表/定义列表结构的同时不把领域类型引进表现层；`view_mapper` 是领域→DTO 的唯一映射处 |
| 3 | 缓存键四要素（doc_id + version + palette + font_size_q） | 漏任何一个都对应一个实测缺陷：切 tab 预览不动 / 改字号主题不重建 / 浮点抖动每帧重建；doc_id 优先级高于版本号（版本号不可跨文档比较） |
| 4 | 防抖计时打在编辑时，不在渲染完成时 | 打在渲染完成会退化成节流（实测 1.2s 连续输入重解析 7 次 vs 验收上限 2 次） |
| 5 | `sync_document` 作为「换文档即重置」唯一入口 | `active_doc` 有 7 处赋值，逐个补重置必然漏（原先一个都没有，正是「切 tab 预览仍是第一份文档」的成因）；改成「拿本次要渲染的 doc_id 与上次比」后与切换动作从哪来无关 |
| 6 | 块矩形每帧重新采集，不跨帧复用 | 立即模式下块位置随宽度/字号/图片解码变化；大图片解码完成那一帧用旧矩形会跳错块 |
| 7 | 图片占位高度固定 96pt | 高度为 0 会让解码完成那一帧整页高度突变、所有块矩形下移——滚动同步跳位；固定后块布局与加载结果无关 |
| 8 | 图片纹理缓存键 = 引用字符串，不设淘汰上限 | 同一张图在多个文档引用只解码一次；条目数有界于用户内容 |
| 9 | 任务回写走与编辑区同源的 `ReplaceRangeCommand` | 可撤销、推进版本号、触发预览重解析；「预览勾上、源码没变」的双真相被结构性排除 |
| 10 | 预览区代码块与编辑区共用同一 `SyntaxHighlighter` | 两套解析器会立刻产生色差；`HighlightSnippetQuery` 直接收文本，代码块不必知道自己的文档偏移 |
| 11 | 公式/图表内置引擎：解析 → 排版（纯函数）→ 绘制 | KaTeX/MathJax 是 JS（无运行时）、resvg 带 C 依赖、且 panic=abort 下第三方 unwrap 即进程终止；度量注入使排版规则可无头断言 |
| 12 | 子集外写法回退源码卡并**写明原因** | 只显示源码，用户的下一步是去查 Mermaid/LaTeX 语法——而多半是编辑器不支持；写明原因立刻说清责任归属 |
| 13 | 表格自绘而非 `egui::Grid` | Grid 列宽来自「愿意收缩到的最小宽度」，表头短正文长的表被压成六七行；改测量+占比分配（长列拿大头、保底 64pt） |
| 14 | 竖线在整行画完后统一补 | 各行高度不等，顺手画会得到长短不齐的短线；行距置 0 + 单元格 pad_y 提供纵向留白 |
| 15 | 每个块 `id_salt(block.id)` | `ui.scope` 子 Ui 的 id 在同一父级下相同，标题撞 id 会被 egui 套红框（2026-10-10 实测） |
| 16 | 预览跟随编辑区「自动换行」开关 | 两栏行为一致：开 → 正文在面板内折行；关 → 长行靠底部横向滚动条；代码块恒不折行（折行破坏缩进可读性） |
| 17 | 滚动同步：块映射 + 块内插值 + 时间抑制窗 + 主动方单一 | 比例同步在高度不均时违反「误差 ≤ 1 块」；比对写入值会被夹紧骗过；两栏互驱形成反馈环（松手后还抖） |
| 18 | 一切外部坐标吸附字符边界（DEF-04） | span 与文本未必同源（150ms 防抖窗口内文本可能又变过）；越界切片在 panic=abort 下是崩溃级回归 |
| 19 | 渲染失败退化一句话而非空白/崩溃 | 预览是增强视图，编辑区永远可用；降级必须明确告知（FR-06「文档过大，预览已降级」） |
| 20 | 预览区标题栏与编辑区工具栏等高、边距与 SidePanel 对齐 | 两栏顶栏与内容区从同一条水平线起——历史上 CentralPanel 默认 6pt 内边距让预览比编辑区低 4pt，是「两栏错位」的回归根源 |
