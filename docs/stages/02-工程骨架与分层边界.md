## 1. 阶段目标

建立**能编译、能校验、能持续集成**的工程骨架，并把需求文档 §6.4 的分层依赖规则变成**机器强制**的约束。本阶段结束时，工程应当"什么功能都没有，但任何违反架构的写法都无法通过提交门禁"。

## 3. 任务清单

### S2-02 模块文件树（空模块声明）

- **描述**：按需求文档 §7.1 创建全部目录与文件，`shared/` 下 5 个、`domain/` 下 5 个上下文目录（每个 6 个文件）、`application/` 下 5 个上下文目录 + `dto.rs`、`infrastructure/` 下 7 个子目录、`presentation/` 下 5 个子目录。每个文件仅含 `pub mod` 声明或空占位 + 一行 `//!` 模块说明。**禁止 `mod.rs`**，一级模块用 `xxx.rs`，子模块放 `xxx/` 目录。

- **验收标准**：`cargo check` 零警告通过；`find src -name mod.rs` 输出为空；`find src -name '*.rs' | wc -l` 与需求文档 §7.1 文件数一致（± 允许后续新增）；每个文件首行有 `//!` 说明。

### S2-03 `shared/error.rs`：统一错误与结果类型

- **描述**：定义 `AppError`（`thiserror` 枚举：`Io`、`Domain`、`Parse`、`Highlight`、`Export`、`Dialog`、`Config`、`Cancelled`）与 `AppResult<T>`；提供 `From<std::io::Error>` 等转换；**不引入 `anyhow` 到此处**（`anyhow` 仅允许在 `app.rs` 与二进制入口使用）。
- **前置依赖**：S2-01
- **涉及文件**：`src/shared/error.rs`、`tests/shared/error_test.rs`
- **验收标准**：`cargo test --test error_test` 通过；单测覆盖：错误转换、`Display` 文案非空、`AppError` 满足 `Send + Sync + 'static`（编译期断言 `fn assert_send_sync<T: Send + Sync>() {}`）；`cargo clippy --all-targets -- -D warnings` 通过。

### S2-04 `shared/ids.rs`：强类型 ID

- **描述**：定义 `DocumentId`、`WorkspaceId`、`AssetId`、`JobId`，均为新类型（`#[derive(Clone, Copy, PartialEq, Eq, Hash, PartialOrd, Ord)]` + `Display`），内部用 `u64` 或 `Uuid`；提供 `new_v4()` / `from_u64()` / `as_u64()`。为避免体积开销，优先使用 `u64` + 进程内单调计数器（不引入 `uuid` crate）。
- **前置依赖**：S2-01
- **涉及文件**：`src/shared/ids.rs`、`tests/shared/ids_test.rs`
- **验收标准**：单测覆盖：同值相等、异值不等、`Display` 稳定、ID 不跨类型混用（编译期不实现 `From<DocumentId> for WorkspaceId`）；`cargo tree | grep -c uuid` 为 0。

### S2-05 `shared/geometry.rs`：文本坐标值对象

- **描述**：定义 `ByteOffset(usize)`（带 `Add`/`Sub`）、`TextRange { start, end }`（`new` 归一化、`len`、`contains`、`is_empty`、`intersects`、`clamp`）、`LineCol { line, col }`、`Rect`-类的轻量几何（可选，供滚动同步用）。
- **前置依赖**：S2-01
- **涉及文件**：`src/shared/geometry.rs`、`tests/shared/geometry_test.rs`
- **验收标准**：单测覆盖：反向区间被 `new` 归一化、`contains` 边界（开闭区间语义明确）、`clamp` 越界行为、`intersects` 真值表（6 种相对位置）；所有方法无 `panic`（越界返回 `Option` 或饱和值）。

### S2-06 `shared/event.rs`：领域事件与事件总线抽象

- **描述**：定义 `DomainEvent` 枚举（`DocumentOpened`、`DocumentSaved`、`TextModified`、`WorkspaceChanged`、`PreferencesChanged`、`ExportFinished`）与 `EventBus` trait（`publish(&self, DomainEvent)`、`subscribe(&mut self, Handler)`，要求 `Send + Sync`）；定义 `EventHandler` 类型别名 `Arc<dyn Fn(&DomainEvent) + Send + Sync>`。**事件枚举在 shared，具体事件载荷用 ID 引用而非聚合实体**（避免 shared 反向依赖 domain）。
- **前置依赖**：S2-03、S2-04
- **涉及文件**：`src/shared/event.rs`
- **验收标准**：`cargo check` 通过；`EventBus` trait 的方法签名满足 `Send + Sync` 约束（用 `fn _assert<T: EventBus + Send + Sync>() {}` 编译期断言）；事件枚举变体数与需求文档 §6.1 各上下文职责对应。

### S2-07 `build.rs` / `check-arch`：分层依赖边界校验

- **描述**：实现架构校验器：扫描 `src/**/*.rs`，按文件路径判定所属层（`domain` / `application` / `infrastructure` / `presentation` / `shared` / `app.rs`），解析 `use` 语句，按需求文档 §7.2 矩阵判定违规（如 `src/domain/**` 出现 `use egui` / `use std::fs` / `use syntect` / `use pulldown_cmark` 即违规）。两种运行方式：`build.rs` 在每次编译时跑（快速失败）+ `src/bin/check-arch.rs` 供人工/CI 单独执行并打印违规文件行号。
- **前置依赖**：S2-02
- **涉及文件**：`build.rs`、`src/bin/check-arch.rs`、`tests/arch_violation_fixture.rs`
- **验收标准**：① 在 `src/domain/document/aggregate.rs` 临时加入 `use egui;` 后，`cargo run --bin check-arch` 退出码非 0 且输出含文件名与行号；② 移除后退出码 0；③ `build.rs` 在违规时 `panic!` 并打印同样信息；④ 校验器自身能识别 `crate::` 与相对路径两种写法。
- **注意事项**：`build.rs` 全量扫描会拖慢增量编译，需缓存「文件 mtime + 校验结果」，仅在源文件变更时重扫。
  - ⚠️ **该缓存已被证伪并移除**：实测「文件 mtime + 校验结果」缓存会让**注入的违规被静默跳过**（cargo 判定脚本无需重跑 + 脚本自身缓存命中，两层条件任一漏判都会放行）。当前 `build.rs` 每次运行都**无条件全量扫描**，是否重跑交由 cargo 依据 `cargo:rerun-if-changed=src` 判断。扫描 100+ 文件仅毫秒级，缓存收益远小于漏检风险。
- **后续加固**：判定逻辑已在 **R-01**（§4.1）重写为**词法 + use-tree 展开**，修掉 8 类漏检（`pub use` / 嵌套花括号 / 跨行 / 别名 / 层根文件 / `src/app/` 整层逃逸 / `crate::app` 无禁令 / `print!` 家族）。判定口径以 `docs/spec/architecture-constraints.md` §4.1 为准。

## 4. 技术方案要点

- **边界校验必须机器化**：分层规则写在文档里必然腐化。校验器扫描 `use` 语句而非 AST 全解析（无 syn 依赖、构建快），牺牲对宏内引用的识别换取零额外依赖与体积。
- **`shared` 的克制**：`shared` 不许反向依赖 `domain`。事件枚举只携带 ID 与标量载荷，具体语义由订阅方自行查询，避免共享内核膨胀成"第二个领域层"。
- **`panic = "abort"` 的连带影响**：会禁用 `catch_unwind`，因此所有测试必须走返回值而非 panic 捕获；同时 `panic = "abort"` 下 `unwrap()` 失败即进程终止——这强化了「生产代码禁用 `unwrap()`」的规范（阶段 03 起执行）。
- **`opt-level = "z"` + `lto = true`** 会显著拉长 release 编译时间（预计 3–8 分钟）。建议 CI 的 PR 检查用 dev profile 跑测试，仅 release job 用完整 profile。

## 5. 风险与注意事项

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| `build.rs` 拖慢编译 | 中 | 每次 `cargo check` 多等数秒，Agent 迭代体验变差 | mtime 缓存；提供 `SKIP_ARCH_CHECK=1` 环境变量逃生口（CI 不设） |
| 校验器误报 | 中 | 合法代码被拦截，团队绕过校验 | 校验器内置白名单机制（`#[allow(arch::exception)]` + 审批注释），但白名单条目需在 `docs/` 登记 |
| egui 0.37.0 API 不稳定 | 低 | 后续升级破 API | 锁定精确版本；`presentation` 与 `app.rs` 对 egui 的直接使用面收敛到最小（阶段 06 二次封装） |
| `panic = "abort"` 与测试冲突 | 低 | 部分测试写法不可用 | 阶段 03 起所有领域逻辑以 `Result` 返回，不靠 panic 表达错误 |
| 三平台 CI 心智负担 | 低 | macOS/Linux 上的平台差异问题延后暴露 | CI 从本阶段就跑三平台，不等到阶段 09 |
