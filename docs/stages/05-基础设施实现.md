## 1. 阶段目标

用具体外部库实现领域层定义的全部 trait，同时守住三条底线：**体积预算**（§8.1）、**不 panic**（越界与 IO 错误一律 `Result`）、**不泄漏外部类型**（对外只暴露领域类型）。

本阶段是需求文档 §8.1 体积预算的**实际验证点**：syntect 若裁剪不当将直接击穿 10 MB 目标，因此 S5-03 必须与体积测量同步推进（M1 起 CI 体积监控，§10 风险表）。

## 3. 任务清单

### S5-01 `RopeTextBuffer`（ropey 实现）

- **描述**：用 `ropey::Rope` 实现 `TextBuffer`：`insert` / `remove` / `slice` / `byte_to_line_col` / `line_col_to_byte` / `line_start_byte` / `snapshot`。全部方法 `Send + Sync`；越界返回 `Result` 或饱和值并 `log::warn!`；**不 `panic!`**。`slice` 优先返回 `Cow<str>` 避免大文件拷贝。
- **前置依赖**：S3-02
- **涉及文件**：`src/infrastructure/text/rope_text_buffer.rs`、`tests/infrastructure/rope_buffer_test.rs`
- **验收标准**：`insert_at_offset` / `remove_range` / `slice_range` / `byte_to_line_col_roundtrip` / `snapshot_is_independent` 五组用例通过；大文件（1MB）随机 1000 次编辑不 panic、耗时线性（记录基线数字）；`cargo bloat --release --crates \| grep ropey` ≤ 0.2 MB。

### S5-02 `PulldownMarkdownParser`

- **描述**：用 pulldown-cmark 0.13（`default-features = false`）实现 `MarkdownParser`：遍历事件流产出 `Vec<RenderedBlock>`，**每个块携带 `source_range`**（用 `OffsetIter` 的 `into_offset_iter()` 获取源码区间）；支持 P0 特性（标题、列表、引用、代码围栏、GFM 表格、任务列表、图片、链接、脚注）；`BlockMapper::offset_to_block` 用二分查找定位块并计算块内比例。
- **前置依赖**：S3-09、S3-10、ADR-002
- **涉及文件**：`src/infrastructure/parsing/pulldown_parser.rs`、`tests/infrastructure/pulldown_parser_test.rs`
- **验收标准**：golden 测试 ≥ 20 条（对照原型 `marked` 渲染结果中可迁移的结构断言：块类型、层级、顺序、源码区间）；10KB 文档解析耗时 ≤ 5ms（`NFR-PERF-06`，用 `criterion` 或简单计时断言，记录基线）；`offset_to_block` 对块首/块中/块尾/空隙四类输入的返回稳定；`cargo bloat` 中 pulldown-cmark ≤ 0.5 MB。

### S5-03 `SyntectHighlighter`（含语言集裁剪与 dump）

- **描述**：syntect 5.3（`default-features = false` + `["parsing", "default-syntaxes", "dump-load", "regex-fancy"]`，纯 Rust）：① 语法集与主题集在**构建期 dump 为二进制**（`build.rs` 或独立 bin 生成 `.bin`，运行期 `from_dump` 加载，约 23ms）；② 语言集按 ADR-002 裁剪到 20 种；③ 实现 `highlight` 与 `highlight_range`（增量，返回 `Vec<SyntaxSpan>`）；④ 语言别名映射表（原型 `CodeDialog.vue` 的 20 种 ↔ syntect 语法名）。
- **前置依赖**：S3-10、ADR-002
- **涉及文件**：`src/infrastructure/highlighting/syntect_highlighter.rs`、`build.rs`（dump 生成）、`tests/infrastructure/highlighter_test.rs`
- **验收标准**：① `cargo bloat --release --crates \| grep syntect` ≤ 1.5 MB，超出则继续裁剪语言集或改用 regex 高亮 fallback（§10 风险应对）；② 20 种语言各有一条 golden 用例（断言 span 数量与起止偏移）；③ dump 加载耗时 ≤ 30ms（冷启动预算内，记录基线）；④ 增量 `highlight_range` 与全量 `highlight` 在相同行上产出一致结果（一致性用例，防增量实现跑偏）；⑤ 未知语言名回退到纯文本不高亮，返回 `Ok(空 spans)` 而非 `Err`。

### S5-04 `FsDocumentRepository`（原子保存）

- **描述**：实现 `DocumentRepository`：`load(path)`、`save(doc)` 采用**原子写**（同目录写 `.tmp` → 落盘 → `rename` 覆盖，对齐 `FR-04`）、`exists`、`delete`。编码处理：UTF-8 with/without BOM 识别，CRLF/LF 归一化为内部 LF、写回时保留原换行风格（`DocumentMeta` 记录 `line_ending`）。草稿恢复：临时目录存放未保存内容，异常退出后可恢复（需求 §4.3）。
  - **读取侧编码探测（2026-10-08 补）**：解码已抽到 `infrastructure/persistence/encoding.rs`，按 UTF-8 BOM → UTF-16 BOM → 裸 UTF-8 → GBK 兜底分级探测。**此前直接用 `String::from_utf8_lossy` 兜底，会把 GBK 文件的每个字节变成 U+FFFD，且保存后不可逆丢失原文**。GBK 用内嵌映射表（`gbk_table.bin`，47880 字节，零新增依赖）解码；写入仍统一为 UTF-8。
  - **判据**：无 BOM 且非合法 UTF-8 时，按"合法 UTF-8 三字节序列数 > 双字节序列数"判定是"损坏的 UTF-8"还是"真 GBK"——真中文是三字节序列，而 GBK 字节偶然凑出的合法序列几乎只落在双字节区。
- **前置依赖**：S3-06、ADR-003
- **涉及文件**：`src/infrastructure/persistence/fs_document_repository.rs`、`tests/infrastructure/fs_document_repository_test.rs`
- **验收标准**：原子保存用例：写入过程中模拟失败（临时文件路径权限错误 / 中断）→ 原文件字节不变；BOM 与 CRLF 往返一致；草稿写入与恢复往返一致；全部错误返回 `AppError::Io` 且带路径信息，无 `unwrap()`。

### S5-07 `InProcessEventBus`

## 4. 技术方案要点

- **体积是本阶段的硬指标**：每完成一个子模块就跑一次 `cargo bloat --release --crates 20`，把数字写进 `docs/spec/metrics.md`。syntect 是最大不确定项，S5-03 应最先开工（可与 S5-01/S5-02 并行），一旦超预算立即触发裁剪或 fallback。
- **golden 测试优先于断言式测试**：解析与高亮的输出结构复杂，用固定语料 + 快照比对能同时防回归与暴露差异；语料选择要覆盖原型已验证过的 Markdown 特性集。
- **安全清洗规则来自原型实测**：原型的 8 条 sanitize 用例是真实踩过的坑，直接作为 Rust 侧的验收标准，比重新设计一套规则更可靠。
- **错误全部 `Result`**：`panic = "abort"` 下任何 `unwrap()` 都会直接终止进程，对编辑器这类长驻应用不可接受。

## 5. 风险与注意事项

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| syntect 体积击穿预算 | 高 | release 产物 > 10 MB | S5-03 优先做；语言集裁剪到 20 → 10 → 5 分级预案；最终 fallback 为自研 regex 高亮（仅覆盖 Markdown 代码围栏常见 token），并在 ADR-002 记录触发阈值 |
| dump 生成跨平台失败 | 中 | 某平台构建期无法生成语法集 dump | dump 生成失败的回退路径：运行时从 `.sublime-syntax` 源码加载（慢但可用），并在启动日志提示 |
| pulldown `default-features = false` 缺特性 | 中 | GFM 表格/脚注解析失效 | S5-02 建立特性清单单测，逐特性验证启用状态；把实际启用的 feature 名写进 ADR-002 |
| 原子写在 Windows 上 rename 失败 | 中 | 目标文件被占用（如被其他程序打开）导致保存失败 | 保存失败返回明确 Err 并保持脏标记；阶段 07 三平台实测（含文件被 Excel/浏览器占用场景） |
| 图片内存占用 | 中 | 大图解码后纹理占用高 | 解码后按显示宽度降采样；LRU 上限可配置；1MB 样本验证内存曲线 |
| 依赖间接膨胀 | 中 | 某个传递依赖拉入大量代码 | `cargo tree` 与 `cargo bloat` 每次提交比对；新增依赖需登记体积贡献（S1-08 规则） |

### 出口遗留（转阶段 08）

1. **首次高亮的冷启动延迟**：某语言首次出现时要反序列化其语法上下文
