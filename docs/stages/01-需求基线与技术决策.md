## 3. 任务清单

### S1-01 冻结需求基线，落地 `REQUIREMENTS.md`

- **验收标准**：`grep -c 'FR-\|FUNC-\|NFR-' REQUIREMENTS.md` ≥ 40；随机抽 5 条能反查到需求文档 v2.0 的具体章节号；P0 条目清单与 §3.1 表格逐行一致（人工比对）。

### S1-02 ADR-001：UI 框架选型（egui vs Tauri）

- **描述**：记录并裁决冲突——原型 `docs/DESIGN-OVERVIEW.md` §1 声明「目标态为 Tauri v2（Rust core + SQLite + WebView）」，而需求文档 §5.2 明确拒绝 Tauri（依赖 WebView、体积 3–10 MB 不稳定、启动 317ms+）。结论：**采用 egui + eframe（当前锁定 0.37.0，2026-10-16 由决策时的 0.33.3 升级），wgpu 后端**；原型中的「SQLite + HTTP/IPC 后端契约」不作为 v1.0 范围。
- **前置依赖**：无
- **涉及文件**：`docs/adr/ADR-001-ui-framework.md`
- **验收标准**：ADR 含「决策 / 备选方案 / 各自代价 / 冲突来源 / 影响范围」五段；明确写出被废弃的原型假设（Tauri、SQLite、后端 HTTP 契约）及其影响（后端接口契约文档降级为 v1.1+ 参考）；评审签字。

### S1-03 ADR-002：Markdown 解析与语法高亮

- **描述**：确定 pulldown-cmark 0.13（`default-features = false` + `["html"]`：仅 HTML 导出需要 `push_html`，GFM 表格/任务列表/脚注是运行期 `Options` 而非 feature）与 syntect 5.3（`default-features = false` + `["parsing", "default-syntaxes", "dump-load", "regex-fancy"]`，纯 Rust 无 onig），并给出**语言集裁剪清单**（首版保留 20 种：rust/python/js/ts/json/html/css/md/bash/toml/yaml/go/java/c/cpp/sh/sql/xml/dockerfile/ini/diff，与原型 `CodeDialog.vue` 的 20 种语言对齐）与**语法集 dump 方案**（构建期生成二进制，运行期加载约 23ms）。
- **前置依赖**：S1-02
- **涉及文件**：`docs/adr/ADR-002-parser-highlighter.md`
- **验收标准**：语言清单与原型 `CodeDialog.vue` 语言表一一对应并给出 syntect 语法名映射（如 `js` → `JavaScript`、`ts` → `TypeScript`）；写明 `default-features = false` 后需显式开启的 feature 名；写明 dump 生成时机（build.rs 或独立 bin）与失败回退策略（回退到源码语法集加载，仅影响启动时间）。

### S1-04 ADR-003：持久化、文件对话框与导出

- **描述**：确定① 文件读写走 `rfd` + 领域层 `DocumentRepository` trait，保存采用**原子写**（临时文件 + `rename`，对齐 `FR-04`）；② 配置持久化用 `serde` + `toml`，含 schema 版本号与迁移策略；③ 图片资源：`data:image/(png|jpeg|gif|webp);base64,` 精确白名单放行，**拒绝 `data:text/html`**（原型 1.4 缺陷的正面经验）；④ PDF 导出（P1）采用系统打印/导出对话框外置方案，不内嵌 PDF 引擎。
- **前置依赖**：S1-02
- **涉及文件**：`docs/adr/ADR-003-persistence-export.md`
- **验收标准**：ADR 写明原子保存的落盘步骤（同目录临时文件 → fsync → rename）与失败回滚；写明 toml schema 版本字段与「版本不匹配时回默认 + 备份原文件」策略；PDF 方案写明三平台各自的系统调用路径与降级提示文案。

## 4. 技术方案要点

- **可追溯性优先**：所有后续任务单元编号（如 `S3-08`）反向映射到需求条目（`FR-03` / `FUNC-P0`），任何任务都能回答「不做它会违反哪条需求」。
- **ADR 只记决策，不记实现**：实现细节下沉到对应阶段文档，避免两份文档互相漂移。
- **原型不是代码来源**：原型的 Vue/TS 实现不可移植到 Rust，仅提取**可观测行为**（输入 → 输出、交互序列、边界文案）。原型的 `lib/` 纯函数（格式化、查找、diff、sanitize 规则）可作为**测试用例来源**：其行为断言直接转为 Rust 侧的 golden 测试。
- **冲突显式化**：Tauri vs egui 的冲突必须在 ADR-001 中写明「原型的后端契约文档 `DESIGN-BACKEND-CONTRACT.md` 在 v1.0 不生效」，避免阶段 05/06 实施时被旧文档误导。

## 5. 风险与注意事项

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| 旧文档误导 | 高 | 实施阶段误读原型 `DESIGN-OVERVIEW.md` 的 Tauri 目标态，做出 SQLite/后端假设 | ADR-001 显式废弃该假设；`docs/spec/architecture-constraints.md` 开头加「已废弃假设」段 |
| ADR 未冻结即开工 | 中 | 阶段 03 完成后才发现 UI 框架决策变更，领域层大量返工 | 阶段 01 DoD 未满足前，禁止创建 `src/` |
| 需求条目编号缺失 | 中 | 后期无法判断某功能是否为 P0，范围蔓延 | S1-01 强制每条需求有编号，PR 描述必须引用编号 |
| 原型契约提取不完整 | 中 | Rust 侧重犯原型已修的缺陷（如撤销跨文件污染） | S1-06 的 B 清单逐条落到具体阶段任务的验收标准里，而非停在文档 |
| 体积预算无依据 | 中 | 后期加入 logging/i18n 等库击穿 10MB | S1-08 起任何新增依赖需估算体积贡献并登记 |
| 测量口径不统一 | 低 | 阶段 08 的「达标」争议 | S1-07 先书面化口径，阶段 08 只填数字 |
