## 1. 阶段目标

实现**完全不依赖任何 UI 与外部库（除 ropey / regex / chrono / serde / thiserror）**的领域层，把 Markdown 编辑器的全部业务规则收敛到可单测的纯逻辑中。领域层是本项目的正确性核心，也是唯一要求 90% 覆盖率的一层。

## 4. 技术方案要点

- **领域层零 IO**：文件读写、目录遍历、对话框全部由基础设施层实现 trait。领域层用 `FilePath` 值对象而非 `std::path::PathBuf`，既避免 IO 依赖，也让路径规则（重名、越界、相对路径）可单测。
- **撤销栈归属权**：撤销历史是 `Document` 的成员而非全局资源，从类型系统层面消除原型「跨文件污染」这一整类缺陷；同理合并窗口状态也是 per-document。
- **`source_range` 前置设计**：Markdown 值对象携带源码区间，是 FR-02（双向滚动同步）与 FR-03（增量高亮）能否实现的决定因素。若此阶段省略，阶段 06 需要返工重解析。
- **快捷键冲突判定在领域层**：把「哪些 combo 允许、哪些冲突」做成可单测的纯规则，而不是散落在 UI 匹配器里的 `if`（原型四处真相问题的根治手段）。
- **trait 对象 vs 泛型**：`Document` 持有 `Box<dyn TextBuffer>`，牺牲一点性能换取可测试性与编译速度；ropey 实现在阶段 05 注入。

## 5. 风险与注意事项

| 风险 | 等级 | 表现 | 应对 |
|---|---|---|---|
| 领域层被 IO 污染 | 高 | 图方便在 `Document` 里直接 `std::fs::write` | `check-arch` 拦截 + CI 门禁；S3-11 明确 `FilePath` 值对象 |
| 撤销语义与用户预期不符 | 中 | 合并窗口过短产生过多撤销点、过长丢失历史 | 窗口取值 `400ms` 为初值，阶段 07 用真实输入节奏校准；把窗口做成 `Preferences` 可配置项 |
| 值对象膨胀 | 中 | `RenderedBlock` 为覆盖所有 GFM 特性而变得臃肿 | 严格按需求文档 §3.1 的 P0 特性设计，P1（数学公式、Mermaid）先以 `BlockKind::Raw` 预留扩展位——**已于 2026-10-08 兑现为 `BlockKind::Math` / `BlockKind::Diagram`**，未改动既有变体与架构 |
| 90% 覆盖率难以达成 | 中 | 大量 `derive` 与简单访问器拉低比例 | 覆盖率统计排除 `errors.rs` 的 `Display` 实现与纯 `derive` 代码，并在 `docs/` 记录排除清单与理由 |
| `panic = "abort"` 下测试难写 | 低 | 期望 panic 的用例无法用 `#[should_panic]` 语义稳定验证 | 领域层全部返回 `Result`，不设计 panic 路径；越界一律 `Err` |
| 领域事件与 UI 状态双写 | 中 | 事件与 UI 直接改状态导致两处不一致 | 事件仅作通知；UI 状态以应用层 DTO 为准，事件只触发重查询 |

## 7. 实现补充说明（阶段 03 落地时新增）

### 7.1 与需求文档 §7.1 文件树的 4 处偏差

| # | 偏差 | 原因 |
|---|---|---|
| 1 | `FilePath` 放在 `shared/path.rs`，而非 `domain/workspace/value_objects.rs` | `document`（保存路径）、`export`（目标路径）、`preferences`（配置路径）都要用；放在 `workspace` 会让 `document` 反向依赖 `workspace`，违背上下文映射（§6.5）。作为 Shared Kernel 上移是唯一自洽方案。 |
| 2 | `DomainEvent` 新增 `SelectionChanged { document_id, selection }` | 否则 `From<DocumentEvent> for DomainEvent` 无法成为全函数（选区事件无处可去）。映射为「仅通知」，订阅方不得据此重解析。 |
| 3 | 不引入 `chrono`，改用 `shared/time::{Timestamp, Clock}` | 规范第 21 条要求时间行为必须**可注入**（撤销合并窗口、自动保存），直接读系统时间无法单测；且领域层只需要毫秒标量与比较，`chrono` 纯属体积负担。 |
| 4 | `markdown` 上下文只有 `aggregate / errors / services / value_objects` | 解析结果是从 `Document` 派生的缓存（`RenderedDocument`），不独立落盘、不独立产生领域事件，故不设 `events` / `repository` 子模块。 |

### 7.2 关键设计决策

- **撤销栈归属 `Document`**（`undo.rs`）：撤销栈与「上次提交类型/时刻」一起作为聚合私有状态，
  从类型系统层面消除原型「全局 `lastCommit` 导致跨文件污染」这一整类缺陷。
- **`source_range` 前置**：`RenderedBlock` 携带源码字节区间，是 `FR-02`（滚动同步）与
  `FR-03`（增量高亮）的前提；`BlockMapper::offset_to_block` 的边界语义（块首/块尾/空隙/零长度块）
  已写入文档注释并由 8 条用例固化。
- **快捷键规则两处收敛**：`KeyCombo::parse` + `display` 是唯一字符串转换/显示源，
  `ShortcutTable::conflicts` 是唯一冲突判定（只报告、不拒绝，故 `Escape` / `F5` 可绑定）。
- **`EditingService` 不硬编码缩进宽度**：`indent_unit: &str` 由调用方从 `Preferences::indent_unit()`
  传入，根治原型缺陷 2.2。
- **导出 TOC 转义下沉**：`TocEntry::new` 计算 `needs_escape`，`TocBuilder::verify` 是兜底防线，
  `TocBuilder::escape_title` 供导出器消费——三者共用 `NEEDS_ESCAPE_CHARS` 常量，避免两处漂移。
